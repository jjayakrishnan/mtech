DP vs Monte Carlo vs TD

You know DP and MC. TD is the third major family of methods. Each answers the same question — "how good is this state?" — in a different way.

Everyday picture — three ways to estimate a house price

DP: you have the full blueprint and pricing model. You calculate value room by room, using a neighbour's estimated value to shortcut the rest.
MC: no model. Wait for the actual sale price, then work backwards.
TD: no model, and you can't wait for the sale. After each open house you update your estimate using your current best guess of the final price.

PropertyDynamic ProgrammingMonte CarloTD Learning
Needs a model?YesNoNo
Needs full episode?NoYesNo

TD is the only method that is both model-free and online. That makes it the default choice when the environment is live, continuous, or too slow for full episodes.

TD(0) — the Update Rule

The simplest TD method is TD(0). It updates a state's estimated value after each single step — no waiting for the episode to end.

From Monte Carlo to TD

In Monte Carlo, we update using the actual total return \(G_t\):

\( V(S_t) \leftarrow V(S_t) + \alpha \bigl[ G_t - V(S_t) \bigr] \)

where \(G_t\) is the discounted sum of all future rewards. We must wait until the episode finishes to compute it.

In TD(0), we replace \(G_t\) with a one-step estimate called the TD target:

\( V(S_t) \leftarrow V(S_t) + \alpha \bigl[\underbrace{R_{t+1} + \gamma V(S_{t+1})}_{\text{TD target}} - V(S_t)\bigr] \)
What each symbol means
  • \(V(S_t)\) — our current estimate of state \(S_t\)'s value
  • \(\alpha\) — the learning rate: how big a step we take (e.g. 0.1)
  • \(R_{t+1}\) — the reward received after the next step
  • \(\gamma\) — the discount factor: future rewards are worth less (0 to 1)
  • \(V(S_{t+1})\) — our current estimate of the next state's value
  • \(\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\) — the TD error: how wrong we were
Intuition — driving home

You estimate the drive will take 30 minutes. Ten minutes in, traffic is light. You now think the total will be 25 minutes. The TD error is "I was off by 5 minutes; adjust my initial estimate slightly." You don't need to arrive home to make that correction.

TD Target and TD Error

Two terms appear constantly. Make sure you can tell them apart in an exam answer.

TD Target = new estimate

\(R_{t+1} + \gamma V(S_{t+1})\). This is what we believe the value of \(S_t\) should be, based on one step of experience. It combines the reward we just got with our current guess of the next state.

TD Error \(\delta_t\) = surprise

\(\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\). This is how far our old estimate was from the new one. Positive means we were too pessimistic. Negative means too optimistic.

Bias–variance trade-off

MC uses the true return — unbiased but high-variance (a long noisy trajectory). TD uses an estimate — biased at first, but low-variance (only one step of noise). As \(V\) improves, the bias drops. This is a core idea in all of RL.

SARSA — On-Policy TD Control

TD(0) updates state values \(V(s)\). For control — actually choosing actions — we need action-value estimates \(Q(s,a)\): "how good is taking action \(a\) in state \(s\)?"

SARSA is the on-policy TD algorithm for learning \(Q\). Its name comes from the five things it uses each step:

The SARSA quintuple

S  →  A  →  R  →  S′  →  A′

State · Action · Reward · Next-State · Next-Action

The SARSA update rule

\( Q(S_t,A_t) \leftarrow Q(S_t,A_t) + \alpha \bigl[ R_{t+1} + \gamma Q(S_{t+1},A_{t+1}) - Q(S_t,A_t) \bigr] \)

This looks exactly like TD(0) but uses \(Q(S,A)\) everywhere. The TD target is \(R_{t+1} + \gamma Q(S_{t+1},A_{t+1})\). We need to know the next action \(A_{t+1}\) before we can update — that's what makes it on-policy.

On-policy means cautious

The next action \(A_{t+1}\) is chosen by the current policy (e.g. ε-greedy). So SARSA respects the policy's caution. If the policy sometimes wanders near a cliff, SARSA learns to stay away from it.

Initialise Q(s,a) ← 0 for all s, a
For each episode:
  S ← initial state
  A ← choose A from S using policy (e.g. ε-greedy on Q)
  Repeat:
    Take action A; observe R, S′
    A′ ← choose A′ from S′ using policy
    Q(S,A) ← Q(S,A) + α[R + γQ(S′,A′) − Q(S,A)]
    S ← S′;  A ← A′
  Until S is terminal

Why does the "old" value stay 1 in all three methods below?

The question asks for the first update using 1-step SARSA, separately using 2-step SARSA, separately using 2-step TD — three independent "what-if" branches, not a chain where one feeds the next. Each branch starts fresh from the same given Q-table (\(q(x,\text{left})=1\)), because the whole point is to compare how differently each method updates the same starting estimate from the same episode.

Part (a) — 1-step SARSA

Looks 1 real reward ahead (R₁), then bootstraps off \(Q(S_1,A_1)\). Since S₁,A₁ = (x, right):

\( \text{target} = R_1 + \gamma\, Q(S_1,A_1) = R_1 + \gamma\, q(x,\text{right}) \)
\( \text{target} = 16 + 0.5(2) = 16 + 1 = 17 \)
\( q(x,\text{left}) \leftarrow \underbrace{1}_{\text{old}} + \underbrace{0.1}_{\alpha}\big(\underbrace{17}_{\text{target}} - \underbrace{1}_{\text{old}}\big) = 1 + 0.1(16) = 1+1.6 = \mathbf{2.6} \)

Part (a) — 2-step SARSA

Looks 2 real rewards ahead (R₁, R₂), then bootstraps off \(Q(S_2,A_2)\). Since S₂,A₂ = (x, left):

\( \text{target} = R_1 + \gamma R_2 + \gamma^2 Q(S_2,A_2) = R_1 + \gamma R_2 + \gamma^2 q(x,\text{left}) \)
\( \text{target} = 16 + 0.5(12) + 0.25(1) = 16+6+0.25 = 22.25 \)
\( q(x,\text{left}) \leftarrow 1 + 0.1(22.25-1) = 1+0.1(21.25) = 1+2.125 = \mathbf{3.125} \)

Part (a) — 2-step TD (expected bootstrap)

Same idea as 2-step SARSA, but instead of bootstrapping off the one specific action A₂ that the episode happened to record, it bootstraps off \(V(S_2)\) — the policy-weighted average over all actions at S₂:

\( V(S_2) = \pi(\text{left}\mid x)\,q(x,\text{left}) + \pi(\text{right}\mid x)\,q(x,\text{right}) = 0.9(1)+0.1(2) = 1.1 \)
\( \text{target} = R_1+\gamma R_2+\gamma^2 V(S_2) = 16+6+0.25(1.1) = \mathbf{22.275} \)
\( q(x,\text{left}) \leftarrow 1 + 0.1(22.275-1) = 1+0.1(21.275) = 1+2.1275 = \mathbf{3.1275} \)

Key insight — the pattern across the whole table

SARSA always locks onto whatever single action the recorded trajectory happened to take next. Expected-value TD hedges across every possible action, weighted by how likely the policy is to pick each one. The arithmetic shell — old + α × (target − old) — never changes; only what goes into target changes.

Part (b) — Can tiling handle a 3-D space with unequal dimension importance?

Answer

Yes, but not with plain uniform tiling. A standard tiling uses the same tile width along every axis, which implicitly treats all three dimensions as equally important/equally fast-changing. To reflect unequal importance you must use non-uniform (asymmetric) tile widths per dimension — narrower tiles (finer resolution) along the dimension that matters more or changes value quickly, wider tiles along the dimension that matters less. So tiling itself isn't ruled out; you just can't use one tile size for all three axes.

Two other feature-construction techniques that handle this naturally:

  • Radial Basis Functions / coarse coding — give each dimension its own receptive-field width, so a "circle" (or ellipsoid) can be stretched to be narrow along important dimensions and wide along unimportant ones.
  • Polynomial or Fourier basis functions — assign a different degree/frequency per dimension, so the function approximator can represent fine detail along important dimensions while staying coarse along the rest.

Part (c) — Why is Q-Learning off-policy?

Answer — starting from the update expression
\( Q(S,A) \leftarrow Q(S,A) + \alpha\big[R+\gamma\max_a Q(S',a) - Q(S,A)\big] \)
  1. The target uses \(\max_a Q(S',a)\) — the value of the greedy action at S′ — regardless of which action the agent's actual behaviour policy (e.g. ε-greedy) takes next.
  2. This means Q-Learning is always learning the value of the greedy target policy, while the data used to generate experience can come from a different, more exploratory behaviour policy — that mismatch between "policy being learned" and "policy being followed" is the definition of off-policy.
  3. Contrast with SARSA's target \(R+\gamma Q(S',A')\), which plugs in the action \(A'\) actually taken next by the same policy generating the data — on-policy, by construction.
Takeaways for the exam
  • Every TD-family update has the same shell: old + α × (target − old). Only the target changes between TD(0), SARSA, Q-Learning, Expected SARSA, and n-step versions.
  • "n-step" = how many real rewards from the episode you trust before switching to a Q-table/V-table bootstrap. n=1 → SARSA target; n=2 → two real rewards then bootstrap; n=∞ → Monte Carlo (no bootstrap at all).
  • SARSA's bootstrap uses one specific recorded action; expected-value TD's bootstrap averages over the whole policy distribution at that state — memorise this one-line distinction, it's a favourite exam trap.
  • When several methods are compared on the "first update," they all restart from the same given Q-table — never chain one method's result into the next unless the question explicitly says so.
  • Q-Learning is off-policy because its target always uses \(\max_a Q(S',a)\) — the greedy policy's value — no matter what the behaviour policy actually does next.

Q-Learning — Off-Policy TD Control

Q-learning is almost identical to SARSA. The only difference is one word: instead of using the actual next action \(A_{t+1}\), it uses the best possible next action.

The Q-Learning update rule

\( Q(S_t,A_t) \leftarrow Q(S_t,A_t) + \alpha \Bigl[ R_{t+1} + \gamma \underbrace{\max_{a'} Q(S_{t+1},a')}_{\text{greedy over all actions}} - Q(S_t,A_t) \Bigr] \)

Instead of needing to first pick \(A_{t+1}\), we look ahead and ask: "what is the best action available from the next state?" That max-Q step is what makes it off-policy.

Off-policy means learn the best, follow anything

You can explore randomly (follow a safe, cautious policy) while simultaneously learning the values for the optimal greedy policy. The max-Q update says "assume we would behave optimally from the next state onwards" — even if we wouldn't in practice.

Initialise Q(s,a) ← 0 for all s, a
For each episode:
  S ← initial state
  Repeat:
    Choose A from S using policy (e.g. ε-greedy)
    Take action A; observe R, S′
    Q(S,A) ← Q(S,A) + α[R + γ maxa′Q(S′,a′) − Q(S,A)]
    S ← S′
  Until S is terminal
(No A′ needed before the update!)

Q-learning converges to the optimal action-value function \(q^*\) as long as every state-action pair is visited often enough.

Manual trace — falling into the −100 pit

Say the agent starts at z and takes action "exit". S = z, A = exit, R = −100, S′ = terminal.

\( Q(z,\text{exit}) \leftarrow 0 + 1 \cdot [-100 + 0.9 \cdot 0 - 0] = \mathbf{-100} \)

Next episode: agent at y, considers "go to z". Q-learning needs maxa′ Q(z, a′) = max(Q(z, exit), Q(z, go-y)) = max(−100, 0) = 0. So no propagation yet. But once Q(z, go-y) also turns negative through more episodes, the penalty propagates all the way back. Eventually the agent learns the safe path to +10.

Exam trap

SARSA and Q-learning have the same update structure. The only difference is Q(S′,A′) vs max Q(S′,·). If an exam question asks you to trace one step of each, that's the line that differs.

Expected SARSA

SARSA uses the actual next action \(A_{t+1}\). Q-learning uses the max. Expected SARSA uses the expected Q value, weighted by how likely the policy is to pick each action.

\( Q(S_t,A_t) \leftarrow Q(S_t,A_t) + \alpha \Bigl[ R_{t+1} + \gamma \sum_{a'} \pi(a'|S_{t+1})\,Q(S_{t+1},a') - Q(S_t,A_t) \Bigr] \)

Sampling a single action (SARSA) adds noise. Taking the expectation removes that noise. Expected SARSA usually converges more smoothly, at the cost of one extra summation per step.

Example with ε-greedy (ε = 0.1, 2 actions)

\(Q(s',a_1) = 10\), \(Q(s',a_2) = 2\). Under ε-greedy: \(a_1\) chosen with probability 0.95, \(a_2\) with 0.05.

\(\mathbb{E}_\pi[Q(s',a')] = 0.95 \times 10 + 0.05 \times 2 = 9.6\)

SARSA would use 10 or 2 depending on which action was sampled. Expected SARSA always uses 9.6 — more stable.

Maximisation Bias & Double Learning

Q-learning uses \(\max_{a'} Q(s',a')\). This looks harmless, but causes a problem: maximisation bias.

The problem

Suppose true optimal action values are all zero, but our estimates have random noise. The max over noisy estimates is almost always positive — we are systematically over-optimistic.

The unreliable friends problem

Ten friends each give you a slightly wrong restaurant rating. You pick the highest rating you heard. Because you took the max of noisy guesses, the chosen restaurant will likely disappoint. The max of noise is biased upward.

The fix — Double Learning

Maintain two independent Q-tables, \(Q_1\) and \(Q_2\). Use one to select the best action, the other to evaluate it:

\( Q_1(S,A) \leftarrow Q_1(S,A) + \alpha\bigl[R + \gamma Q_2\bigl(S',\;\arg\max_{a'}Q_1(S',a')\bigr) - Q_1(S,A)\bigr] \)

By separating selection from evaluation, the upward bias cancels. Trade-off: double the memory for Q tables, same computation per step. This is the idea behind Double DQN.

Exam tip

Whenever you see \(\max\) over estimated values in RL, ask: "could this be biased upward?" Double learning is the standard fix.

n-step TD

TD(0) looks one step ahead. Monte Carlo looks all the way to the end. n-step TD lets you choose any depth in between.

The n-step return

\( G_{t:t+n} = \sum_{k=1}^{n} \gamma^{k-1} R_{t+k} + \gamma^n V(S_{t+n}) \)

At \(n=1\) this is TD(0). As \(n \to \infty\), the \(\gamma^n V(S_{t+n})\) term shrinks to zero and we get the full MC return.

Key insight

n-step TD unifies TD(0) and Monte Carlo under one formula. In practice, \(n\) is a hyperparameter you tune: small \(n\) is fast but uses a biased bootstrap; large \(n\) is more accurate but slower and noisier.

Which Method When?

This was a major focus in Session 9. The professor used three concrete use cases.

Scenario (from class)Best methodReason
Chess robot Dynamic Programming Rules of chess are fixed. Full model dynamics known. Can plan ahead without sampling.
Ball-throwing robot arm Monte Carlo No exact physics model, but episodes are clear (ball lands or misses). Can wait for episode feedback. Full-episode returns natural here.
Autonomous car in live traffic TD Learning Can't wait for an "episode" to end. No fixed model. Needs step-by-step online updates. Exactly what TD was designed for.
Three questions to ask (from the lecture)
  1. Are model dynamics available and fixed? → If yes, consider DP.
  2. Do episodes terminate in reasonable time? → If yes and no model, consider MC.
  3. Do you need real-time online updates? → If yes, use TD.
