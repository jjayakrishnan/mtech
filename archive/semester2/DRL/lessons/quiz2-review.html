Returns & Discounting

The Return Formula

Core Formula

The return from time step t is:

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}$$

How to compute from a specific state

If the reward sequence from state 6 (Start) to state 1 (End) is R6=40, R5=0, R4=0, R3=0, R2=0, R1=100, and we want G₄ (return from state 4), only use rewards from state 4 onwards:

$$G_4 = R_4 + \gamma R_3 + \gamma^2 R_2 + \gamma^3 R_1 = 0 + 0 + 0 + (0.25)^3 \times 100 = 1.5625$$
Exam Trap

Don't include rewards from states before your starting state. The return at state 4 does NOT include R6 or R5.

Effect of γ on Bellman

γ = 0

  • Agent is completely myopic
  • \( V(s) = R(s) \)
  • Only immediate reward counts
  • Future discounted to zero

γ = 1

  • All future rewards count equally
  • Valid only for episodic tasks (finite horizon guarantees convergence)
  • NOT valid for continuing tasks (sum may diverge)

Multi-Armed Bandits

The Four Methods — Side by Side

ε-Greedy

  • With prob (1−ε): take best-known action (exploit)
  • With prob ε: take a random action (explore)
  • Simple; ε must be in [0, 1]
  • Does NOT target under-explored arms specifically

UCB (Upper Confidence Bound)

  • Select arm with highest: \( Q(a) + C\sqrt{\dfrac{\ln t}{N_t(a)}} \)
  • Bonus grows when arm is rarely tried
  • Automatically prioritises under-explored arms
  • Best when you need equal opportunity for all arms

Gradient Bandit

  • Learns preference h(a), not value estimates
  • Selects via softmax: \( \pi(a) = \dfrac{e^{H(a)}}{\sum_b e^{H(b)}} \)
  • Updates h(a) using gradient ascent after each reward
  • Does NOT need reward distribution in advance
  • α controls preference update magnitude

Sample Average (α = 1/n)

  • Averages all observed rewards equally
  • Converges to true mean for stationary problems
  • Fails for non-stationary: old stale data gets same weight as recent data
  • Fix: use constant α (e.g. 0.1) for exponentially weighted recency

Optimistic Initialisation

Analogy

Setting initial estimates to 10 (when true rewards are in [0,1]) is like assuming every slot machine is amazing. The moment you try one and it pays ≤1, you're disappointed — and that makes all the untried machines still look like 10. So you're forced to try them all. For deterministic rewards, one visit = exact true value → greedy from there onwards is optimal.

When to Increase ε

  • High reward variance: your estimates are noisy; more exploration → better estimates
  • Non-stationary (q* changes): optimal arm can shift; must keep exploring to track it
Exam Trap

If the agent has already found the optimal arm (stationary, low variance), ε should be reduced, not increased. Only explore more when you can't trust your current estimates.

MDP Fundamentals

Markov Property

Definition

The future is independent of the past, given the present:

$$P(S_{t+1} \mid S_t, A_t) = P(S_{t+1} \mid S_0, A_0, \ldots, S_t, A_t)$$

Only the current state and action matter — not the history.

MDP Components

SymbolNameExample (self-driving car)
\(S\)State spaceTraffic signal status, vehicle positions, pedestrian locations
\(A\)Action spaceSteering angle, accelerator, brake
\(R\)Reward function+5 for reaching destination, −5 for unsafe proximity
\(P\)Transition functionProbability of next traffic state given current + action
\(\gamma\)Discount factorHow much to value future rewards (0 to 1)

Evaluative vs Instructive Feedback

Evaluative (RL)

  • Tells you how good the action you took was
  • Does not say what the best action would have been
  • Signal: scalar reward R
  • Agent must explore to discover better actions

Instructive (Supervised)

  • Tells you exactly what the correct output should be
  • Provides a label/target for every input
  • Signal: gradient of loss function
  • No exploration needed — the answer is given

Bellman Equations

State-Value Function V_π(s)

Bellman Expectation Equation
$$V_\pi(s) = \sum_a \pi(a|s) \sum_{s',r} p(s',r|s,a)\bigl[r + \gamma V_\pi(s')\bigr]$$

Action-Value Function q_π(s, a)

Formula
$$q_\pi(s,a) = \sum_{s',r} p(s',r|s,a)\bigl[r + \gamma V_\pi(s')\bigr]$$

For deterministic transitions: \( q_\pi(s,a) = R + \gamma \cdot V(s') \)

Worked Example (Q14)

Grid World

4×4 grid, γ=1 (undiscounted episodic), R=−1 for every transition.
V(row 3, col 4) = −14. Calculate q_π((row 2, col 4), down).

"Down" from (2,4) leads to (3,4):

$$q_\pi\bigl((2,4),\text{down}\bigr) = -1 + 1 \times (-14) = -15$$

Bellman Optimality Equation

V*(s) — Recursive Definition
$$V^*(s) = \max_a \sum_{s',r} p(s',r|s,a)\bigl[r + \gamma V^*(s')\bigr]$$

V*(s) is defined in terms of V*(s'): recursive. This is the backbone of Dynamic Programming in RL.

Dynamic Programming: Policy & Value Iteration

Policy Iteration

  • Step 1 — Evaluate: compute V_π for current policy
  • Step 2 — Improve: greedily update policy w.r.t. V_π
  • Repeat until stable
  • Guarantees convergence to optimal policy
  • Best for constrained problems (safety + objective)

Value Iteration

  • Combines evaluation + improvement in one sweep
  • Directly iterates the Bellman Optimality Equation
  • Faster per iteration; converges to V*
  • Extracts optimal policy from V* at the end
When to Pick Which

Policy Iteration — when you need to reason about the policy itself at each step (e.g. checking safety constraints per-step). Value Iteration — when you just want V* as fast as possible.

Reward Function Design

A reward function must encode both the primary goal and constraints (safety, efficiency). The classic pitfalls:

Design ChoiceProblem
+10 for slowing at signalsIncentivises trivial mandatory behaviour above the actual goal
0 for slowing at signalsNeutral — gives agent no reason to behave safely there
Only reward safe distance from vehiclesDoesn't capture reaching the destination — agent may park forever
+5 arrive earliest, −5 near pedestrianCorrect: rewards goal, penalises safety violation
Rule of Thumb

The reward function should be a proxy for what you actually care about. Reward the outcome (reaching destination quickly), penalise violations (unsafe proximity). Avoid rewarding intermediate steps that could be gamed.

Common Exam Traps

TrapWhat to Remember
Computing G from state k Only use rewards from state k onward. Don't include earlier rewards.
γ = 1 is "wrong" γ = 1 is valid and often correct for episodic tasks. It's only invalid for continuing tasks where the sum can diverge.
ε-greedy "always chooses best" Only with prob (1−ε). With prob ε it's purely random — the estimate is ignored.
UCB = exploration UCB is optimism-under-uncertainty — it's still greedy but with an exploration bonus. It's not random exploration.
Gradient bandit needs distribution It does NOT. It learns from observed rewards only — no prior knowledge of distribution required.
"Improve policy" = RL goal Improving the policy is the mechanism. The goal is maximising cumulative reward.
Sample-average works everywhere Only for stationary problems. For non-stationary, use constant α to forget old data.
ε can be negative or > 1 ε must be in [0, 1]. ε = −1 or ε = 10 are invalid.

Self-Test Drill

Try each question before opening the answer.

Returns

  1. Reward sequence: R5=10, R4=0, R3=0, R2=50. γ=0.5. What is G3?
    Show answer

    G3 = R3 + γR2 = 0 + 0.5×50 = 25

  2. If γ=0, what does V(s) simplify to?
    Show answer

    V(s) = R(s) — only the immediate reward, since all future terms are multiplied by zero.

Bandits

  1. You have a 5-armed bandit, stationary, low variance. Should ε be large or small?
    Show answer

    Small. Low variance + stationary means your estimates are reliable. No need to keep exploring — exploit the best known arm.

  2. Why does optimistic initialisation (init=5, true rewards ∈ [0,1]) force exploration?
    Show answer

    Every arm looks like it gives 5. When you try one and get ≤1, its estimate drops below 5. All untried arms still look like 5, so the greedy agent picks them next. It's forced to try all arms before settling.

  3. What's wrong with using sample-average for a non-stationary bandit?
    Show answer

    Sample average gives equal weight to all past observations. If the reward distribution shifts, old (stale) data drags the estimate away from the current truth. Use constant α instead.

Bellman & Grid World

  1. In a 4×4 grid, γ=1, R=−1 everywhere. V(s') = −18. What is q_π(s, right) if right leads to s'?
    Show answer

    q_π(s, right) = −1 + 1×(−18) = −19

  2. Why is V*(s) called a "recursive" definition?
    Show answer

    Because V*(s) is expressed in terms of V*(s') — the value of the current state depends on the value of the next state, which itself uses the same formula.

Policy vs Value Iteration

  1. An energy management system must minimise power while keeping safety at each time step. Which DP method fits better?
    Show answer

    Policy Iteration. The explicit policy evaluation step lets you reason about whether the current policy satisfies safety constraints, then improve it. Value Iteration finds V* without tracking the policy explicitly at each step.
