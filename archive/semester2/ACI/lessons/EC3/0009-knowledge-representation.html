Knowledge-Based Agents

Every agent we have seen so far — search agents, game-playing agents — encodes the world as a state and searches over it. Those agents cannot say why a state is good. They cannot learn a new rule mid-game. They just evaluate numbers.

A knowledge-based (KB) agent works differently. It stores facts about the world in a Knowledge Base (KB) and reasons from those facts to decide what to do next.

Everyday picture — detective vs. GPS

A GPS routes you by running Dijkstra over a graph. It has no idea why a road is blocked. A detective reasons: "Road X is blocked because of the match; matches end at 22:00; therefore it will clear by 22:15." The detective uses a KB of facts and inference rules. That is a KB agent.

The Knowledge Base

The KB is a set of sentences written in a formal knowledge representation language. Each sentence either:

  • states a fact directly (axiom), or
  • was derived from other sentences by inference (derived fact).

Every KB agent performs three operations on each tick:

OperationMeaningExample
TELLAdd a new sentence to the KBTELL(KB, "There is a breeze at [2,1]")
ASKQuery the KB for what is knownASK(KB, "Is [3,1] safe?")
TELL (action)Record the action takenTELL(KB, "Agent moved Forward")
Why not just use a database?

A database stores facts but cannot infer new ones. If the DB knows "All pits cause breezes" and "There is a breeze at [2,1]", it cannot conclude anything about nearby cells unless the programmer hard-codes every combination. A KB agent uses logic to derive new facts automatically.

Exam trap

TELL and ASK are interface operations, not data structures. The KB itself is the set of sentences. Students sometimes confuse "the KB" with "the TELL/ASK interface" — they are different things.

The rest of this lesson builds the reasoning machinery: how to write sentences (propositional logic, first-order logic), and how to draw conclusions from them (truth tables, resolution, forward/backward chaining).

Propositional Logic

To reason formally, we need a language with a precise grammar (syntax) and precise meaning (semantics).

Analogy — a formal contract

Natural language is ambiguous: "I saw the man with the telescope" has two meanings. A legal contract is precise — every clause has exactly one interpretation. Propositional logic is the contract language of AI: every sentence has one definite truth value.

Syntax: what sentences look like

A sentence (also called a formula) is built from:

  • Atomic sentences — symbols like \( P \), \( Q \), \( B_{2,1} \) — each is either True or False.
  • Logical connectives that combine atoms into complex sentences.
SymbolNameRead asTrue when…
\( \neg P \)Negation (NOT)"not P"P is False
\( P \wedge Q \)Conjunction (AND)"P and Q"both P and Q are True
\( P \vee Q \)Disjunction (OR)"P or Q"at least one of P, Q is True
\( P \Rightarrow Q \)Implication (IF...THEN)"P implies Q"P is False, OR both are True
\( P \Leftrightarrow Q \)Biconditional (IFF)"P if and only if Q"P and Q have the same truth value
Precedence (highest to lowest)

\( \neg \) binds tightest, then \( \wedge \), then \( \vee \), then \( \Rightarrow \), then \( \Leftrightarrow \). So \( \neg P \wedge Q \Rightarrow R \) parses as \( ((\neg P) \wedge Q) \Rightarrow R \).

Semantics: what sentences mean

A model is an assignment of True/False to every atomic sentence. With \(n\) atoms, there are \(2^n\) models. A sentence is satisfiable if it is true in at least one model, and valid (a tautology) if true in every model.

Exam trap — implication is not causation

\( P \Rightarrow Q \) is True when P is False — even if Q has nothing to do with P. Example: "If pigs fly, then 2+2=4" is a true sentence in propositional logic. Implication only becomes False when P is True but Q is False.

Wumpus World in propositional logic

Let \( B_{i,j} \) mean "there is a Breeze at cell \([i,j]\)", and \( P_{i,j} \) mean "there is a Pit at \([i,j]\)". Then:

\( B_{1,1} \Leftrightarrow (P_{1,2} \vee P_{2,1}) \)

This says: there is a breeze at [1,1] if and only if there is a pit in an adjacent cell. This one sentence captures the breeze-pit relationship for [1,1]. We need a similar sentence for every cell — that is the limitation of propositional logic (addressed by FOL later).

Truth Tables and TT-Entailment

Now the big question: given a KB full of sentences, can we conclude a new sentence \(\alpha\)? This is logical entailment.

Entailment — formal definition

The KB entails \(\alpha\), written \( KB \models \alpha \), if and only if \(\alpha\) is true in every model where the KB is true.

In other words: there is no possible world where everything in the KB is true but \(\alpha\) is false.

$$ KB \models \alpha \;\iff\; M(KB) \subseteq M(\alpha) $$

where \(M(KB)\) is the set of models in which the KB is satisfied, and \(M(\alpha)\) is the set of models in which \(\alpha\) is satisfied.

Analogy — "all swans are white"

If your KB is "all swans are white; Cygnus is a swan", then you are entitled to conclude "Cygnus is white" because in every possible world consistent with the KB, Cygnus is indeed white. There is no escape.

The TT-Entail algorithm

The simplest way to check \( KB \models \alpha \) is to enumerate all \(2^n\) models (truth table rows) and check: whenever KB is true, is \(\alpha\) also true?

function TT-ENTAILS(KB, α):
  symbols ← list of all proposition symbols in KB and α
  return TT-CHECK-ALL(KB, α, symbols, {})

function TT-CHECK-ALL(KB, α, symbols, model):
  if symbols is empty:
    if KB is true in model: return (α is true in model)
    else: return True -- KB false → row doesn't matter
  else:
    P ← first(symbols); rest ← rest(symbols)
    return TT-CHECK-ALL(KB, α, rest, model ∪ {P=True})
        AND TT-CHECK-ALL(KB, α, rest, model ∪ {P=False})
Complexity — why TT-Entail is impractical

With \(n\) symbols, TT-Entail checks \(2^n\) rows. For 100 symbols that is \(2^{100} \approx 10^{30}\) rows — more than the number of atoms in the Earth. TT-Entail is a correct but impractical algorithm. We need proof-based methods (resolution, DPLL) for real problems.

Worked example — Wumpus inference

KB: \( R_1: \neg P_{1,1} \), \( R_2: B_{1,1} \Leftrightarrow (P_{1,2} \vee P_{2,1}) \), \( R_4: \neg B_{1,1} \). Query: \( \neg P_{1,2} \).

From \( R_4: \neg B_{1,1} \) and \( R_2 \), we know \( \neg(P_{1,2} \vee P_{2,1}) \), i.e., \( \neg P_{1,2} \wedge \neg P_{2,1} \). So \( \neg P_{1,2} \) is entailed. TT-Entail would verify this by checking all 8 possible (P₁₁, P₁₂, P₂₁) assignments and confirming that every row where R₁, R₂, R₄ are all True also has \( \neg P_{1,2} \) True.

Proof by Resolution

Instead of enumerating all models, can we prove a conclusion by symbol manipulation? Yes — using resolution, a single powerful inference rule.

The Resolution Rule

Given two clauses that contain a literal and its complement:

$$ \frac{A_1 \vee \cdots \vee A_k \vee P \qquad \neg P \vee B_1 \vee \cdots \vee B_m}{A_1 \vee \cdots \vee A_k \vee B_1 \vee \cdots \vee B_m} $$

The conclusion is the resolvent: the two clauses merged with \(P\) and \(\neg P\) cancelled out.

Analogy — cancelling terms in algebra

Resolution is like combining two equations. If I know \(x + y = 10\) and \(x - y = 2\), I can add them to get \(2x = 12\), eliminating \(y\). Resolution eliminates a literal by "adding" two clauses.

Proof by contradiction (refutation)

To prove \( KB \models \alpha \):

  1. Assume \( \neg\alpha \) (the negation of what we want to prove).
  2. Add \( \neg\alpha \) to the KB.
  3. Apply resolution repeatedly.
  4. If we derive the empty clause \(\{\}\) — a contradiction — then our assumption was wrong, so \(\alpha\) must be true.
$$ KB \cup \{\neg\alpha\} \vdash \{\} \;\Rightarrow\; KB \models \alpha $$

Worked example — Wumpus proof

Proving ¬P₁₂ by contradiction

KB clauses (simplified): (1) \(\neg B_{1,1}\), (2) \(\neg B_{1,1} \vee P_{1,2} \vee P_{2,1}\), (3) \(\neg P_{1,2} \vee B_{1,1}\), (4) \(\neg P_{2,1} \vee B_{1,1}\).

Add negation of query: (5) \(P_{1,2}\).

Step 1: Resolve (3) and (1): \( (\neg P_{1,2} \vee B_{1,1}) + (\neg B_{1,1}) \to \neg P_{1,2} \).

Step 2: Resolve \(\neg P_{1,2}\) with (5) \(P_{1,2}\): \(\neg P_{1,2} + P_{1,2} \to \{\}\) — contradiction!

Conclusion: \( KB \models \neg P_{1,2} \). Cell [1,2] has no pit.

Exam trap — resolution requires clauses

Resolution only applies to clauses — disjunctions of literals. You cannot directly resolve \( (A \wedge B) \) with \( \neg A \). You must first convert everything to CNF (Conjunctive Normal Form). That is the subject of the next section.

CNF Conversion and PL-Resolution

Before applying resolution, every sentence in the KB must be in Conjunctive Normal Form (CNF).

CNF — what it means

A formula is in CNF if it is a conjunction (\(\wedge\)) of clauses, where each clause is a disjunction (\(\vee\)) of literals. A literal is either an atom \(P\) or its negation \(\neg P\).

Example: \( (A \vee B) \wedge (\neg A \vee C) \wedge (B \vee \neg C \vee D) \) is in CNF.

Four-step CNF conversion algorithm

  1. Eliminate biconditionals (↔): Replace \( P \Leftrightarrow Q \) with \( (P \Rightarrow Q) \wedge (Q \Rightarrow P) \).
  2. Eliminate implications (→): Replace \( P \Rightarrow Q \) with \( \neg P \vee Q \).
  3. Push negations in (De Morgan): Move all \(\neg\) inward using \(\neg(P \wedge Q) \equiv \neg P \vee \neg Q\) and \(\neg(P \vee Q) \equiv \neg P \wedge \neg Q\). Double negatives cancel: \(\neg\neg P \equiv P\).
  4. Distribute \(\vee\) over \(\wedge\): Use \( A \vee (B \wedge C) \equiv (A \vee B) \wedge (A \vee C) \) to flatten into pure conjunctions of disjunctions.

Full worked example — converting R₂ to CNF

Step-by-step CNF conversion of R₂

Start: \( R_2: B_{1,1} \Leftrightarrow (P_{1,2} \vee P_{2,1}) \)

Step 1 — Eliminate ↔:

\( (B_{1,1} \Rightarrow (P_{1,2} \vee P_{2,1})) \wedge ((P_{1,2} \vee P_{2,1}) \Rightarrow B_{1,1}) \)

Step 2 — Eliminate →:

\( (\neg B_{1,1} \vee P_{1,2} \vee P_{2,1}) \wedge (\neg(P_{1,2} \vee P_{2,1}) \vee B_{1,1}) \)

Step 3 — Push ¬ in (De Morgan on second clause):

\( (\neg B_{1,1} \vee P_{1,2} \vee P_{2,1}) \wedge ((\neg P_{1,2} \wedge \neg P_{2,1}) \vee B_{1,1}) \)

Step 4 — Distribute ∨ over ∧:

\( (\neg B_{1,1} \vee P_{1,2} \vee P_{2,1}) \wedge (\neg P_{1,2} \vee B_{1,1}) \wedge (\neg P_{2,1} \vee B_{1,1}) \)

Three CNF clauses. Done.

PL-Resolution algorithm

function PL-RESOLUTION(KB, α):
  clauses ← CNF(KB ∧ ¬α)
  new ← {}
  loop do:
    for each pair of clauses (Cᵢ, Cⱼ) in clauses:
      resolvents ← RESOLVE(Cᵢ, Cⱼ)
      if {} ∈ resolvents: return TRUE -- empty clause → proved
      new ← new ∪ resolvents
    if new ⊆ clauses: return FALSE -- no progress → not entailed
    clauses ← clauses ∪ new

Unit resolution — a fast special case

A unit clause is a clause with exactly one literal (e.g., \(\neg B_{1,1}\) or \(P_{1,2}\)). Resolving a unit clause with a longer clause immediately simplifies it:

$$ \{P_{1,2}\} + \{\neg P_{1,2} \vee B_{1,1}\} \;\to\; \{B_{1,1}\} $$

Unit resolution is not complete by itself, but it is the backbone of the DPLL algorithm and Horn clause reasoning.

DPLL Algorithm

DPLL stands for Davis–Putnam–Logemann–Loveland. It is a complete, backtracking-based SAT solver for CNF formulae. "Complete" means it always terminates with a correct answer.

Analogy — smart Sudoku solver

A naive solver tries every digit in every empty cell. DPLL is smarter: when it spots a cell with only one possible digit, it fills it immediately (unit clause). When it spots a digit that appears in only one row, it locks it in (pure symbol). Only when forced does it guess and backtrack.

Three key optimisations over brute force

OptimisationTriggerAction
Early TerminationAll clauses are satisfied by partial assignmentReturn satisfiable immediately — no need to assign remaining symbols
Pure Symbol HeuristicA symbol appears only positively (or only negatively) across all remaining clausesAssign it the value that makes it True in all its clauses — safe, no harm
Unit Clause HeuristicA clause has exactly one unassigned literal (all others are False)Force that literal to be True — no choice

DPLL pseudocode

function DPLL(clauses, symbols, model):
  -- Early termination
  if every clause is TRUE in model: return TRUE
  if some clause is FALSE in model: return FALSE

  -- Pure symbol heuristic
  P, val ← FIND-PURE-SYMBOL(symbols, clauses, model)
  if P is not null: return DPLL(clauses, symbols–P, model∪{P=val})

  -- Unit clause heuristic
  P, val ← FIND-UNIT-CLAUSE(clauses, model)
  if P is not null: return DPLL(clauses, symbols–P, model∪{P=val})

  -- Branching
  P ← first(symbols); rest ← rest(symbols)
  return DPLL(clauses, rest, model∪{P=True})
      OR DPLL(clauses, rest, model∪{P=False})

Worked trace on a small CNF

CNF: \( (A \vee B) \wedge (\neg A \vee C) \wedge (\neg B \vee \neg C) \). Symbols: A, B, C.

DPLL trace

Check pure symbols: A appears positively in clause 1 and negatively in clause 2 — not pure. B appears positively in clause 1 and negatively in clause 3 — not pure. C appears positively in clause 2 and negatively in clause 3 — not pure. No pure symbols.

Check unit clauses: No unit clauses (all clauses have two or more unassigned literals).

Branch: Try \(A = \text{True}\).

  • Clause 1 \((A \vee B)\) → satisfied.
  • Clause 2 \((\neg A \vee C)\) → simplifies to \(C\). Unit clause! Force \(C = \text{True}\).
  • Clause 3 \((\neg B \vee \neg C)\) with \(C = \text{True}\) → simplifies to \(\neg B\). Unit clause! Force \(B = \text{False}\).

All clauses satisfied. Assignment: \(A=T, B=F, C=T\). Satisfiable.

First-Order Logic (Predicate Logic)

Propositional logic is powerful but verbose. To say "breezes occur in all cells adjacent to pits", you need a separate sentence for every cell. In a 4×4 grid that is 16 sentences. In a real world with millions of objects, it is hopeless.

First-Order Logic (FOL), also called Predicate Logic, solves this. Instead of individual boolean symbols, FOL talks about objects, relations, and functions.

Analogy — from postcards to a template

Propositional logic writes one postcard per fact: "John is tall", "Mary is tall", "Bob is tall", …. FOL writes one template: "∀x: Person(x) → Tall(x)" — a single sentence that covers every person at once.

The three ingredients of FOL

IngredientWhat it representsExamples
ConstantsSpecific named objectsJohn, 3, BITS, West, Nono
PredicatesProperties of objects (return True/False)Tall(x), Missile(M1), Enemy(Nono, America)
FunctionsMap objects to objectsFatherOf(John), LeftOf(cell)
VariablesPlaceholders (always bound by a quantifier)x, y, z, p

Atomic and complex sentences in FOL

An atomic sentence in FOL is a predicate applied to terms: \( Missile(M_1) \), \( Owns(Nono, M_1) \), \( Equal(x, y) \).

Complex sentences use the same connectives as propositional logic (\(\neg, \wedge, \vee, \Rightarrow, \Leftrightarrow\)) plus two new quantifiers \(\forall\) and \(\exists\) (covered in the next section).

FOL vs. propositional logic — the key difference

In propositional logic, \(B_{1,1}\) is a fixed boolean — it has one truth value. In FOL, \(Breeze(x)\) is a predicate — it takes an argument, and its truth value depends on what \(x\) refers to. FOL talks about things, not just about truth values.

Models in FOL

A FOL model specifies:

  1. A domain — the set of objects that exist.
  2. An interpretation — which constants map to which objects, which predicates hold of which object tuples.

For example: domain = {West, Nono, M1, America}, with Missile(M1) = True, Owns(Nono, M1) = True, etc.

Exam trap — functions vs. predicates

A function returns an object: \(FatherOf(John)\) returns a person. A predicate returns a truth value: \(Father(x, y)\) is True if x is the father of y. Do not confuse them. Predicates appear as arguments to connectives; functions appear as arguments to predicates.

Quantifiers: ∀ and ∃

Quantifiers let a single sentence speak about many objects at once — the whole power of FOL in two symbols.

Universal quantifier — ∀

∀x — "for all x"

\(\forall x\; \phi(x)\) is True if \(\phi(x)\) is True for every object in the domain.

Read as: "for all x", "for each x", "for every x".

\( \forall x\; Man(x) \Rightarrow Drinks(x, coffee) \)

Read: "For every x, if x is a man, then x drinks coffee." Note the use of \(\Rightarrow\) (not \(\wedge\)) with \(\forall\) — see exam trap below.

Existential quantifier — ∃

∃x — "there exists an x"

\(\exists x\; \phi(x)\) is True if \(\phi(x)\) is True for at least one object in the domain.

Read as: "there exists an x", "for some x", "for at least one x".

\( \exists x\; Boys(x) \wedge Intelligent(x) \)

Read: "There exists an x such that x is a boy and x is intelligent." Note the use of \(\wedge\) (not \(\Rightarrow\)) with \(\exists\).

The single biggest exam trap in FOL

Using the wrong connective with quantifiers is the most common mistake:

  • ∀ uses →: \( \forall x\; Man(x) \wedge Drinks(x,coffee) \) would assert that everything in the domain is both a man and a coffee drinker — almost certainly wrong.
  • ∃ uses ∧: \( \exists x\; Man(x) \Rightarrow Drinks(x,coffee) \) is True if there exists anything that is not a man (because the implication is trivially satisfied by non-men) — almost certainly not what you mean.

Properties of quantifiers

PropertyFormulaMeaning
De Morgan for ∀\( \neg \forall x\; P(x) \equiv \exists x\; \neg P(x) \)"Not all" = "There exists one that isn't"
De Morgan for ∃\( \neg \exists x\; P(x) \equiv \forall x\; \neg P(x) \)"None exists" = "All are not"
Nested ∀∀\( \forall x \forall y\; P(x,y) \equiv \forall y \forall x\; P(x,y) \)Order of ∀ doesn't matter
Nested ∃∃\( \exists x \exists y\; P(x,y) \equiv \exists y \exists x\; P(x,y) \)Order of ∃ doesn't matter
Nested ∀∃ ≠ ∃∀\( \forall x \exists y\; Loves(x,y) \not\equiv \exists y \forall x\; Loves(x,y) \)"Everyone loves someone" ≠ "Someone is loved by everyone"

Universal Instantiation (UI)

A universally quantified sentence can be instantiated for any specific constant \(c\):

$$ \frac{\forall x\; \phi(x)}{\phi(c/x)} $$

Example: from \( \forall x\; Man(x) \Rightarrow Mortal(x) \) and \( Man(Socrates) \), we can instantiate to get \( Man(Socrates) \Rightarrow Mortal(Socrates) \), and then conclude \( Mortal(Socrates) \) by Modus Ponens.

Existential Instantiation (EI)

An existentially quantified sentence introduces a new constant (a Skolem constant) to name the witness:

$$ \frac{\exists x\; \phi(x)}{\phi(k/x)} \quad \text{where } k \text{ is a brand-new constant} $$

Example: from \( \exists x\; Intelligent(x) \), we introduce the constant \(k\) and assert \( Intelligent(k) \). We do not know who \(k\) is, but we know something intelligent exists.

Forward Chaining

Now that we have FOL and Horn clauses, we can do inference efficiently. Forward Chaining is the data-driven approach: start from known facts and keep deriving new facts until the query is answered.

Analogy — a detective building a case

A detective starts with evidence — a fingerprint, a motive, a witness statement. She keeps combining evidence with rules ("fingerprint at scene + suspect owns the gun → suspect present") until she reaches "suspect is guilty". That is forward chaining: evidence → rules → new facts → conclusion.

The Missile World facts and rules

The canonical example used in CS#9 and CS#10:

LabelSentenceType
F1\( Missile(M_1) \)Fact
F2\( Owns(Nono, M_1) \)Fact
F3\( American(West) \)Fact
F4\( Enemy(Nono, America) \)Fact
R1\( \forall x\; Missile(x) \Rightarrow Weapon(x) \)Rule
R2\( \forall x\; Enemy(x, America) \Rightarrow Hostile(x) \)Rule
R3\( \forall x,y\; Owns(Nono,x) \wedge Missile(x) \Rightarrow Sells(West,x,Nono) \)Rule
R4\( \forall x,y,z\; American(x) \wedge Weapon(y) \wedge Sells(x,y,z) \wedge Hostile(z) \Rightarrow Criminal(x) \)Rule

Goal (query): \( Criminal(West) \) — is West a criminal?

Forward Chaining algorithm

function FOL-FC-ASK(KB, α):
  new ← {}
  loop do:
    for each rule (p₁ ∧ … ∧ pₙ → q) in KB:
      θ ← UNIFY(p₁ ∧ … ∧ pₙ, known facts)
      if θ ≠ FAIL:
        q' ← SUBST(θ, q)
        if q' = α: return TRUE
        if q' ∉ KB: new ← new ∪ {q'}
    if new = {}: return FALSE
    KB ← KB ∪ new; new ← {}

Worked trace — proving Criminal(West)

Forward Chaining step-by-step

Iteration 1 — scan all rules:

  • R1 + F1: \(Missile(M_1)\) matches \(Missile(x)\) with \(x=M_1\). Derive \(Weapon(M_1)\).
  • R2 + F4: \(Enemy(Nono, America)\) matches with \(x=Nono\). Derive \(Hostile(Nono)\).
  • R3 + F1 + F2: \(Owns(Nono,M_1) \wedge Missile(M_1)\) matches with \(x=M_1\). Derive \(Sells(West,M_1,Nono)\).

Iteration 2 — new facts enable R4:

  • R4 requires: \(American(West)\) ✓ (F3), \(Weapon(M_1)\) ✓ (new), \(Sells(West,M_1,Nono)\) ✓ (new), \(Hostile(Nono)\) ✓ (new).
  • All premises match with \(x=West, y=M_1, z=Nono\). Derive \(Criminal(West)\).

Query matched! West is a criminal.

Backward Chaining

Backward Chaining is the goal-driven approach. It starts with what you want to prove and works backwards, asking "what facts would I need to prove this?"

Analogy — a lawyer preparing a defence

A lawyer starts with the verdict they need to prove: "My client is innocent." They work backwards: "To prove that, I need an alibi for the night of the crime. To get an alibi, I need a witness." They never go off chasing irrelevant evidence — they pursue only what is needed for the goal.

Backward Chaining algorithm

function FOL-BC-ASK(KB, goals, θ):
  if goals = []: yield θ; return
  q ← first(goals); rest ← rest(goals)
  for each (lhs → rhs) in KB where rhs unifies with q, θ' = UNIFY(rhs, q):
    new_goals ← SUBST(θ', lhs) ++ rest
    for each θ'' in FOL-BC-ASK(KB, new_goals, θ'):
      yield θ''

Key idea: Divide & Conquer. Break the goal into subgoals. Each subgoal is either a known fact (stop), or matches the RHS of a rule (recurse into its LHS premises).

Worked trace — proving Criminal(West) backwards

Backward Chaining step-by-step

Goal: Criminal(West)

Scan KB for rule whose RHS unifies with Criminal(West). Find R4: \(American(x) \wedge Weapon(y) \wedge Sells(x,y,z) \wedge Hostile(z) \Rightarrow Criminal(x)\). Unify with \(x=West\). New subgoals:

  1. \(American(West)\) — known fact F3. ✓
  2. \(Weapon(y)\) — scan KB. R1: \(Missile(x) \Rightarrow Weapon(x)\). Subgoal: \(Missile(y)\). From F1: \(Missile(M_1)\). Bind \(y=M_1\). ✓
  3. \(Sells(West, M_1, z)\) — scan KB. R3: \(Owns(Nono,x) \wedge Missile(x) \Rightarrow Sells(West,x,Nono)\). Subgoals: \(Owns(Nono,M_1)\) (known F2 ✓) and \(Missile(M_1)\) (known F1 ✓). So \(z=Nono\). ✓
  4. \(Hostile(Nono)\) — scan KB. R2: \(Enemy(x,America) \Rightarrow Hostile(x)\). Subgoal: \(Enemy(Nono,America)\) — known F4. ✓

All subgoals satisfied. Criminal(West) is True.

Exam tip — which chaining to use

If the question gives you a goal to prove: use backward chaining (it's goal-focused). If the question asks you to derive everything from a set of facts: use forward chaining. If the question says "data-driven": forward. If it says "goal-driven" or "divide and conquer": backward.
