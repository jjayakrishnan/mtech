Why Compare Three Methods on One Example?

You have now met three families of RL algorithms: Dynamic Programming, Monte Carlo, and Temporal Difference. They all answer the same question — "what is the best action in this state?" — but they use very different information and very different update schedules. Comparing them on an abstract level is hard. Comparing them on the same concrete problem makes the differences sharp and memorable.

Analogy — three routes to the same airport

DP: You have the full map and traffic model. You compute the optimal route for every possible starting point before you leave home.
MC: You drive to the airport, take note of the total journey time, and update your route estimate — but only once you've arrived.
TD: Every few minutes, you adjust your estimated arrival time based on current speed and remaining distance. No map needed, no arrival needed.

The Race Track — A Perfect Benchmark

The race track (Sutton & Barto, Exercise 5.8) is a grid-world with a velocity dimension. It is ideal for comparison because:

  • The model is fully known — so DP can run in full. This is rare in practice, which is why DP serves as the oracle baseline.
  • Episodes terminate naturally at the goal line — so MC can collect complete returns.
  • Steps are expensive (each is a time step in a race) — so TD's online updates make it practical for a real robot.
The race track — physical setup

A car starts at a random position on the bottom row with zero velocity. It must reach the finish line (rightmost column) as fast as possible. Hitting a wall resets the car to the start with zero velocity. The goal is to find the policy that reaches the finish line in as few steps as possible.

Race Car as a Formal MDP

Before comparing algorithms, we need to pin down exactly what the MDP is. Getting the state space right is the first move in any RL problem.

State Space

A naive state is just position \((r, c)\). But that ignores velocity — at the same position you can be going fast or slow, and the optimal action differs. The correct state is:

\( s = (r,\; c,\; v_r,\; v_c) \)

where \((r,c)\) is the grid position and \((v_r, v_c)\) are velocity components, each constrained to \(\{0, 1, 2, 3, 4\}\). On an 8×6 track, the state space has up to \(6 \times 8 \times 5 \times 5 = 1200\) states.

State space anatomy
  • Position \((r,c)\): row 0–5, column 0–7. Row 5 = start line. Column 7 = finish line.
  • Velocity \((v_r, v_c)\): each in \(\{0, 1, 2, 3, 4\}\). Both start at 0. Both-zero is forbidden after the first step (the car must keep moving).
  • Wall states: top-left 2×2 area cells are walls — they have no valid position.

Action Space

At each step the driver applies an acceleration in each dimension:

\( a = (\Delta v_r,\; \Delta v_c) \in \{-1, 0, +1\}^2 \quad \Rightarrow \quad 9 \text{ actions} \)

Velocity clips to \([0,4]\) after applying the acceleration. If a velocity component would drop below 0 it stays at 0; if it would exceed 4 it stays at 4.

Reward and Transition

Reward function

\( R = -1 \) for every step that does not end at the goal. \( R = 0 \) at the goal (episode ends). There is no discount needed if \(\gamma = 1\), since episodes are guaranteed to terminate.

Transition dynamics
  • Normal move: apply \(\Delta v\), move by new velocity \((v_r', v_c')\). New position \((r',c') = (r+v_r', c+v_c')\).
  • Crash (hit wall or boundary): reset to a random start-line cell, velocity = (0,0).
  • Goal: any move that crosses column 7 terminates the episode.
Why velocity in the state?

Imagine two cars at identical positions: one going at speed 4 toward a wall, one at speed 0. The first should brake now; the second should accelerate. Same \((r,c)\), very different optimal action. Without velocity in the state, the MDP is non-Markovian — the future depends on history that the state doesn't capture. Adding velocity makes it fully Markovian.

Why This MDP Is Interesting for Comparison

The race car MDP has a critical property: the transition function \(P(s'|s,a)\) is fully computable from the physics above. This means DP can run. Most real-world MDPs do not have this property — that is exactly why MC and TD were invented.

Dynamic Programming — Policy Iteration

DP treats the race car problem as a planning problem. It needs the full model and performs sweeps over all states until convergence.

The Two-Phase Loop

Policy Iteration alternates between two operations:

  1. Policy Evaluation — given the current policy \(\pi\), compute \(V^\pi(s)\) for every state by iterating the Bellman expectation equation to convergence.
  2. Policy Improvement — update \(\pi\) greedily: in each state, pick the action that gives the best one-step look-ahead value.
$$ V^\pi(s) = \sum_{s'} P(s'|s,\pi(s)) \bigl[ R(s,\pi(s),s') + \gamma V^\pi(s') \bigr] $$
$$ \pi'(s) = \arg\max_a \sum_{s'} P(s'|s,a) \bigl[ R(s,a,s') + \gamma V^\pi(s') \bigr] $$
Initialise V(s) ← 0 for all s; π(s) ← arbitrary for all s

Repeat:
  // ── Policy Evaluation ──
  Repeat:
    Δ ← 0
    For each non-terminal state s:
      v ← V(s)
      V(s) ← Σ_{s'} P(s'|s,π(s)) [R + γ V(s')]
      Δ ← max(Δ, |v − V(s)|)
  Until Δ < θ (convergence threshold)

  // ── Policy Improvement ──
  policy_stable ← true
  For each state s:
    old_action ← π(s)
    π(s) ← argmax_a Σ_{s'} P(s'|s,a) [R + γ V(s')]
    If old_action ≠ π(s): policy_stable ← false

Until policy_stable (policy did not change → optimal)

What DP Knows That MC and TD Don't

The DP advantage — full model sweep
  • At every state \(s\), DP can ask: "if I take action \(a\), where could I end up, and with what probability?" This is \(P(s'|s,a)\).
  • The evaluation step updates all 1200 states simultaneously in each sweep.
  • After 10–20 sweeps, the value function is near-optimal everywhere on the track.
  • The arrows shown in the DP Policy view represent this converged policy.
Exam trap — DP vs planning

DP does not run episodes. It never takes an action in the environment. It computes values purely from the model. If an exam question says "no model available", DP is ruled out immediately.

DP on the Race Car — Computational Cost

For the full Sutton & Barto race track (roughly 3000 reachable states × 9 actions), each policy evaluation sweep requires roughly 27000 Bellman updates. With 10–20 sweeps per evaluation and 5–10 policy improvement rounds, that is around 1–5 million operations. Feasible offline. Not feasible online in a physical car.

Key insight

DP converges to the true optimal policy \(\pi^*\) and true optimal value function \(V^*\). MC and TD approach the same solution but from sampled experience. On the race car, DP's policy arrows tell you the ground truth — the benchmark every other method tries to match.

Monte Carlo ES — Learning Without a Model

Monte Carlo methods replace the model with sampled experience. Instead of computing \(P(s'|s,a)\), we just drive the car, watch what happens, and average the returns.

Exploring Starts (ES)

A key problem with MC on the race car: if we always start from the start row with zero velocity, many state-action pairs will never be visited. We'd never learn how to handle a fast-moving car in the middle of the track. The fix is Exploring Starts: every episode begins with a randomly chosen state-action pair.

Monte Carlo ES — the full algorithm

This is the algorithm from Sutton & Barto Section 5.3, applied directly to the race car.

Initialise Q(s,a) ← 0 for all s, a
             π(s) ← arbitrary greedy policy
             Returns(s,a) ← empty list for all s, a

For each episode:
  Choose S₀, A₀ at random (exploring start — uniform over non-wall pairs)
  Generate episode S₀,A₀,R₁,S₁,A₁,R₂,...,S_T following π

  G ← 0
  For t = T−1, T−2, ..., 0: (backwards through episode)
    G ← γG + R_{t+1}
    Returns(S_t, A_t).append(G)
    Q(S_t, A_t) ← mean(Returns(S_t, A_t))
    π(S_t) ← argmax_a Q(S_t, a) (greedy update)

The Return — MC's Core Computation

The return \(G_t\) is the discounted sum of all rewards from step \(t\) onwards:

\( G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots = \sum_{k=0}^{T-t-1} \gamma^k R_{t+k+1} \)

On the race car, every reward is \(-1\) until the goal. So an episode that reaches the goal in \(T\) steps gives \(G_0 = -T\) (with \(\gamma=1\)). A shorter race = higher return. MC learns to prefer policies that finish quickly.

MC on the Race Car — Strengths and Weaknesses

Why MC works well here
  • No model needed — the car's physics do not need to be specified.
  • Low bias — \(G_t\) is the actual return, not a bootstrapped estimate.
  • Variance comes only from the stochasticity of the path, not from an approximation.
MC limitation — episode dependency

MC requires complete episodes. On the race car, a car that crashes early and restarts may generate short episodes — fine. But in problems without a natural termination (e.g., a car that just keeps driving), MC cannot apply. TD handles those.

TD Learning — SARSA and Q-Learning on the Race Car

TD methods combine DP's bootstrap idea with MC's model-free sampling. Instead of waiting for the episode to end, they update after every single step.

SARSA on the Race Car

SARSA is the on-policy TD variant. After each step, it updates using the quintuple \((S_t, A_t, R_{t+1}, S_{t+1}, A_{t+1})\):

\( Q(S_t,A_t) \leftarrow Q(S_t,A_t) + \alpha \bigl[ R_{t+1} + \gamma\, Q(S_{t+1},A_{t+1}) - Q(S_t,A_t) \bigr] \)

On the race car: the TD target is \(-1 + \gamma\,Q(s',a')\). The car uses its current estimate of how good the next state-action is rather than waiting to discover the final return.

Initialise Q(s,a) ← 0 for all s, a
For each episode:
  S ← random start cell, v ← (0,0)
  A ← ε-greedy action from Q(S, ·)
  Repeat:
    Apply A; observe R, S′
    (R = −1 normally; R = 0 at goal; crash → reset)
    A′ ← ε-greedy action from Q(S′, ·)
    Q(S,A) ← Q(S,A) + α[R + γQ(S′,A′) − Q(S,A)]
    S ← S′; A ← A′
  Until S is the goal

Q-Learning on the Race Car

Q-Learning is the off-policy variant. It uses the maximum Q-value of the next state, regardless of what action the current policy would actually take:

\( Q(S_t,A_t) \leftarrow Q(S_t,A_t) + \alpha \Bigl[ R_{t+1} + \gamma \max_{a'} Q(S_{t+1},a') - Q(S_t,A_t) \Bigr] \)

This means Q-Learning is always learning the optimal policy directly, even if it is currently following a random exploration policy.

SARSA vs Q-Learning on a real track

SARSA evaluates the policy you are actually driving. Near a wall, if you explore and sometimes drive dangerously, SARSA learns that those states are dangerous — and stays away. It learns the value of the exploratory (cautious) policy.

Q-Learning always optimises as if you would drive perfectly from the next state onward. It converges faster to the globally optimal racing line, but during training it may experience more crashes because it doesn't learn to avoid near-wall states as carefully.

TD Error on the race car

At each step: \(\delta_t = R_{t+1} + \gamma\,Q(S_{t+1},A_{t+1}) - Q(S_t,A_t)\).
Since \(R = -1\) always: \(\delta_t = -1 + \gamma\,Q(S_{t+1},A_{t+1}) - Q(S_t,A_t)\).
Early in training, Q ≈ 0 everywhere, so \(\delta_t \approx -1\): every step feels equally bad. Over time, cells near the goal get positive Q signals and the TD error propagates backward step by step, just like in the maze example from Lesson 10.

TD vs MC — convergence intuition

TD updates every step, so it gets \(T\) updates per episode versus MC's 1 update per episode (applied in full at the end). This means TD learns faster in terms of steps taken — but each update is noisier because it bootstraps from an approximate value function. MC updates are unbiased but require a full episode to compute.

The unified picture — bootstrapping vs sampling

All three methods sit on a two-axis grid. Axis 1 (horizontal): whether the estimate uses a model (DP) or samples (MC, TD). Axis 2 (vertical): whether the estimate bootstraps off an intermediate value (DP, TD) or uses the full return (MC). Sutton & Barto's famous "unifying view" diagram shows this exact grid, with TD in the centre combining both dimensions advantageously.

The n-step Bridge

TD and MC are not binary opposites. n-step TD methods sit between them:

\( G_{t:t+n} = \sum_{k=0}^{n-1} \gamma^k R_{t+k+1} + \gamma^n\, Q(S_{t+n}, A_{t+n}) \)

At \(n=1\) you get TD(0). As \(n \to \infty\) the bootstrap term \(\gamma^n Q(\cdot)\) shrinks to zero and you recover the MC return. Choosing \(n\) gives you a bias-variance dial: small \(n\) = low variance, higher bias; large \(n\) = low bias, higher variance.

Exam question pattern — which method for which constraint?

If the exam gives you constraints and asks you to choose: (1) no model → eliminates DP; (2) no complete episode (continuing task, or too long) → eliminates MC; (3) need fast learning → TD wins over MC; (4) model available → DP is optimal; (5) safe exploration required → SARSA over Q-Learning.

Practical Advice — When Would You Use Each for a Real Racing Robot?

The race car was a toy problem. Now imagine you are building an actual autonomous racing robot. Which algorithm do you deploy?

Scenario 1 — Simulated Race Track (Full Model Available)

Use Dynamic Programming

If you have built a simulation with known physics (exact speed, friction, crash conditions), run DP inside the simulator. You get the optimal policy in minutes of offline computation. Deploy that policy to the real robot. The risk: if the real track differs from the simulation (different friction, sensor noise), the DP policy degrades. Sim-to-real transfer is an active research area precisely because DP policies are brittle to model mismatch.

Scenario 2 — Physical Robot, Short Supervised Sessions

Use Monte Carlo

If you run the robot in timed laps and can afford to wait until each lap ends before updating, MC is natural. After each lap, propagate returns backwards through the episode. Good for: slow robots with human-supervised runs. Bad for: robots that crash and require reset after every episode (crash-reset cycles are expensive). Also bad if laps are too long — the robot needs many complete laps before Q-values propagate to the start of the track.

Scenario 3 — Physical Robot, Continuous Real-Time Operation

Use TD — specifically Q-Learning for a racing robot

A real racing robot cannot pause at the end of each lap. It needs to update its Q-values while driving. Q-Learning updates after every control cycle (say 100 Hz), is model-free, and converges to the optimal policy even with random exploration. In practice, you would combine Q-Learning with function approximation (neural network Q-function) to handle the full continuous state space — this is Deep Q-Learning (DQN), the topic of later lessons.

The Decisive Questions

QuestionAnswer → Method
Is the transition model fully known and correct? Yes → DP. No → MC or TD.
Do episodes (laps) end naturally in reasonable time? Yes and model unavailable → MC. No or too long → TD.
Is safety critical during training (near walls)? Yes → SARSA (on-policy, respects exploratory caution). No, want best final policy → Q-Learning.
Is the state space too large for a table? Yes → TD + function approximation (DQN, policy gradient — Lessons 12–13).
Need to learn from a human driver's demonstrations? → Imitation learning combined with TD (Lesson 15).
The big picture

DP, MC, and TD are not competing answers to the same question. They are answers to three different questions about what information you have and when you need to act. For most real autonomous systems — from robots to trading agents to game-playing AI — the answer is TD (or TD + deep learning), because the world is too large to model exactly, and you cannot wait for episodes to end before updating.
