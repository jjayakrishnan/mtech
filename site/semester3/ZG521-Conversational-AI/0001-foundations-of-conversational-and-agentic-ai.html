What Session 1 actually covered

Module 1 — Foundations of Conversational and Agentic AI — is an orientation plus a genuine first concept: the evolution from scripted chatbots to autonomous agents, why an agent needs more than a good language model, and the system-architecture vocabulary (orchestration, memory, tools) you'll keep reusing for the next 15 sessions. The professors explicitly treat this course and ZG536 (LLMs for GenAI) as siblings: "most of you would have taken the other elective called LLM for GenAI, and a few would not have — that is fine, wherever a prerequisite is required we'll quickly brush up." This page is that brush-up, plus the Session 1 content itself.

From Eliza to autonomous agents

The professor opens by asking whether everyone remembers Eliza and Alice from the NLP course — the earliest chatbots, built from the 1960s–90s. Tracing that evolution is the spine of Module 1.

The evolution, compressed
EraHow it workedCeiling
Eliza (1966), Alice (1995)Hand-written pattern-matching rules ("if user says X, reply with template Y")No real understanding — breaks the moment you go off-script
Retrieval / ML chatbotsPick the best-matching canned response from a trained corpusStill bounded by a fixed response set
LLM-based assistants (ChatGPT-era)Generate a fresh response token by token from a decoder-only TransformerFluent, but a one-shot "reasoning model" with no memory and no hands — it can't look anything up or take real action
Autonomous agents (this course)An LLM wrapped in a loop: reason → plan → act (call tools) → observe the result → repeat, with memory across turnsThis is the frontier — reliability, cost, and safety are now the hard problems, not fluency
Analogy — the smartest intern who's never left the office A bare LLM is like an extremely well-read intern who has memorised a huge library but has never once left the building: brilliant at reasoning from what they already know, completely unable to check today's weather, look up your calendar, or send an email. An agent is that same intern now handed a phone, a laptop, and a notebook — tools to act on the world, and memory to remember what happened five minutes ago. The intelligence didn't change; the hands and the memory did.

What actually makes something an "agent"?

The professor is blunt about the old mindset: "my chatbot works" used to mean "it replied something plausible." The new bar is "my agent works correctly, repeatedly, under all conditions" — correctly calling the right tools, every time, not just sounding fluent once.

  • Reasoning — deciding what needs to happen, step by step
  • Planning — breaking a goal into an ordered sequence of actions
  • Tools — the agent's "hands": APIs, search, calculators, code execution
  • Memory — short-term (this conversation) and long-term (across sessions)
  • Autonomy — retrying, adapting, and deciding when to stop on its own, within set limits
Analogy — a trained guide dog vs. a dog that only "sits" A dog that performs one trick on a fixed command ("sit!" → sits) is a chatbot: input in, canned output out. A guide dog is an agent: it perceives a changing environment, plans a safe route, decides moment to moment when to stop and refuse a command (a car is coming), remembers its handler's routines, and acts autonomously within the boundaries of its training. That boundary — real autonomy, inside hard limits — is exactly what Module 4 (security, guardrails, governance) is about: an agent without guardrails is a guide dog with no training at all.

Mechanically, this loop has a name you'll see constantly from Session 4 onward: ReAct (Reason + Act) — the agent writes out a thought, picks a tool action, observes the tool's result, and loops, repeating up to some iteration limit before giving its final answer. "If it goes wrong again, it will go and try several times… if I set that iteration limit to five, that's autonomy," as the professor puts it.

Prerequisites you need

Everything in this course sits on top of a decoder-only LLM — the "brain" doing the reasoning step of every ReAct loop. If tokens, embeddings, attention, and why LLMs are decoder-only aren't solid yet, Session 2 (LLM foundations) and Session 6 (embeddings & retrieval) will be harder than they need to be.

Read first Prerequisites Primer: Attention, Transformers & Encoder-Decoder — specifically the Query/Key/Value section (you'll meet it again when retrieval and "attending over context" come up) and the decoder-only section (every agent's reasoning engine is decoder-only).

Self-check

Q1. What's the single biggest functional difference between a 2020-era LLM chatbot and a 2026-era autonomous agent?
Tools and memory. A bare LLM chatbot can only generate text from what it already "knows" internally and has no way to act on the world or remember prior interactions beyond the current context window. An agent wraps that same kind of model in a reason→plan→act→observe loop with access to external tools (search, APIs, code execution) and persistent memory, letting it look things up, take real actions, and build on past interactions.
Q2. Why does "my agent works correctly, repeatedly, under all conditions" matter more for agents than for a one-shot chatbot reply?
An agent chains multiple autonomous steps (tool calls, retries, iterations) to reach a goal — a single wrong tool call or misread result early in the chain can cascade into a completely wrong outcome several steps later, unlike a one-shot chatbot reply where a bad answer is immediately visible and self-contained. Reliability has to hold across every step of the loop, not just once.
Q3. In the ReAct loop (reason → act → observe → repeat), what stops it from looping forever on a task it can't solve?
An iteration limit set by the system designer — e.g. "try at most 5 times" — after which the agent stops and reports failure (or escalates to a human) rather than looping indefinitely. This is one of the guardrail patterns covered in Module 4.
