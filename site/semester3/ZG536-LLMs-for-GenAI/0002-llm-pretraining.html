Recap: the language-modelling head (finishing Session 1)

The transformer stack turns each input token into a hidden vector of size \( d \) (the model or embedding dimension). But we need a probability for every word in the vocabulary (size \( |V| \)). The LM head bridges that gap with two steps:

$$ \text{logits} = h_{\text{last}} \cdot E^{\top} \qquad\qquad P(\text{next token}) = \text{softmax}(\text{logits}) $$
Analogy — a vote count The hidden vector is a short "summary card" of everything read so far. Multiplying by the embedding table is like asking every word in the dictionary "how well do you match this summary?" — each word returns one score (a logit). Softmax then turns the raw scores into percentages that add up to 100%.

Worked exampleWhy the matrix must be \( d \times |V| \)

Step 1. The last hidden state for one position has shape \( 1 \times d \).

Step 2. We need logits of shape \( 1 \times |V| \) — one score per vocabulary word. Softmax never changes shape, so its input must also be \( 1 \times |V| \).

Step 3. Linear-algebra rule: \( (1 \times d)\cdot(d \times |V|) = (1 \times |V|) \). So the projection matrix is \( d \times |V| \).

Step 4 — weight tying. The input embedding table \( E \) is \( |V| \times d \). Rather than learn a second big matrix, reuse it transposed: \( E^{\top} \) is \( d \times |V| \). Hence the name unembedding. Bonus: a token keeps the same learned meaning on the way in and on the way out.

Step 5 — size check for Llama 3 8B: \( d = 4096 \), \( |V| = 128{,}000 \) → \( 4096 \times 128000 = 524{,}288{,}000 \approx 525\text{M} \) parameters in the embedding (and, being tied, the unembedding) matrix.

  • Greedy decoding = pick the highest-probability token. (Better decoders — top-k, top-p, temperature — come in Modules 4–5.)
  • The unembedding matrix does not add position information again — position was already mixed into the hidden states in the input layer.
  • Inference vs training: at inference only the last position matters (one row, \( 1 \times |V| \)). In training the head runs at every position at once, giving an \( N \times |V| \) matrix for a length-\( N \) sequence — that is what makes training parallel.
  • Context length = the maximum number of tokens (input + output together) the model can process at once. It is fixed by the model's creator, not a setting you choose. BERT: 512 tokens, GPT-2: 1,024; modern models: 100K+. Find it on the model's card (Hugging Face).

Self-supervised learning — free labels

Why is it called pre-training? Because LLM training has two phases: pre-training (read a huge corpus, learn language and general knowledge) and post-training (fine-tune to behave like a classifier, assistant or chatbot). A freshly pre-trained model is not yet "useful for any task".

Analogy — a quiz you write yourself Imagine learning English by covering up the next word of every sentence in a library and trying to guess it. The book itself holds the answer key. Nobody has to label anything, so the quiz can be as big as the library.
  • In ordinary supervised ML, a human supplies labels \( y \). Here the label is taken from the text itself (GPT: the next token; BERT: a hidden token). We only write a script that turns raw text into \( (X, y) \) pairs.
  • These made-up tasks are pretext tasks — not the real goal, but solving them forces the model to learn grammar, facts and meaning.
  • Every token is a free training example. That is why LLM datasets are measured in tokens (not rows, files or GB): 15T tokens = 15 trillion examples.
  • Careful: "15T tokens" counts all tokens, repeats included. Unique tokens are what build the vocabulary (e.g. 128K). The word "the" is one unique token but appears billions of times.

Pre-training objectives

Three architectures, three ways to make "free" labels
FamilyExampleObjectiveWhat happens
Encoder-onlyBERT (2018)Masked LM (MLM)Hide ~15% of tokens; predict them using context on both sides
Encoder-decoderT5 (2019)Span corruption (denoising)Replace spans with sentinels <X>, <Y>; decoder generates the missing spans
Decoder-onlyGPT-2/3, Llama 3, Qwen3, DeepSeek-V3Causal LM (CLM)Predict next token from previous ones only (left → right)
Memorise Modern LLMs use CLM (next-token prediction) because it trains generation directly, which MLM does not. MLM sees both sides, so it is great for understanding tasks but cannot simply write text left to right.

Worked exampleThe same sentence under all three objectives

Sentence: the cat sat on the mat

MLM (BERT): input the cat [MASK] on the mat → target: sat (uses "cat" and "on the mat").

Span corruption (T5): input the cat <X> the mat → decoder outputs <X> sat on </X>.

CLM (GPT): six training examples from one sentence, all at once: the → cat, the cat → sat, the cat sat → on, … on → the, … the → mat. One sentence gave several labelled examples for free.

How training runs: teacher forcing & the loss

  • Teacher forcing: at each position the input is the true previous token, not the model's own guess (unlike at generation time).
  • All positions in parallel: one forward pass computes the loss at every position; the causal mask stops each position from peeking at the future. (This is unlike an RNN, which must go step by step.)
  • Everything is updated: the loss is back-propagated through all weights, including the embeddings.
$$ \mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log P(w_{t+1}\mid w_{\le t}) \qquad\qquad \text{Perplexity} = e^{\mathcal{L}} $$

Worked exampleLoss and perplexity for 4 predictions

Suppose the model gave the correct next token these probabilities: \( 0.5,\ 0.25,\ 0.1,\ 0.4 \).

Step 1 — log each: \( \ln 0.5=-0.693,\ \ln 0.25=-1.386,\ \ln 0.1=-2.303,\ \ln 0.4=-0.916 \).

Step 2 — sum: \( -5.298 \).

Step 3 — average and flip sign: \( \mathcal{L} = 5.298/4 = 1.325 \).

Step 4 — perplexity: \( e^{1.325} \approx 3.76 \).

Reading it: the model is as unsure as if it were choosing among ~3.8 equally likely words at each step. A perfect model has perplexity 1. Lower is better.

The modern LLM pipeline

Pre-training is only the first stage. The modern recipe is:

Raw text → [Pre-training: next-token, trillions of tokens] → BASE model → [Post-training: SFT / instruction tuning → preference alignment (RLHF, DPO)] → INSTRUCT / CHAT model (Sessions 3 & 9)

Why base ≠ assistantSame prompt, two models

Prompt: "What is the capital of France?"Typical output
Base model"What is the capital of Germany? What is the capital of Italy? …" (it continues a list of quiz questions)
Instruct model"The capital of France is Paris."

A base model's job is to continue text. On Hugging Face the two are released separately: Meta-Llama-3.1-8B vs …-Instruct; Qwen3-8B-Base vs Qwen3-8B (which is the post-trained one).

The pre-training data pipeline

The whole idea: raw web text is mostly noise, so a series of stages removes something before the model sees a single token. Sources: Common Crawl, GitHub, arXiv, Wikipedia, books. Open corpora today: FineWeb (15T tokens), RedPajama-V2 (30T), Dolma (3T, used by OLMo), The Stack v2 (code). Before using any source, check licensing and privacy.

Four stages (raw corpus → training-ready)
#StageWhat it removesExample
1FilterLow-quality, spam, wrong-language textAlice is writing a paper. #$^& → junk #$^& removed
2De-duplicateRepeated sentences and near-copy documentsSame paragraph on 50 news sites → keep 1
3Remove PIINames, emails, phone numbers, IDsAlice → [Somebody]; abc@x.com → [EMAIL]
4Tokenize + packWasted paddingByte-level BPE, then doc1 <eos> doc2 <eos> doc3 filling each context window

Filtering — two toolkits

  • Heuristics (cheap): language ID (drop Chinese if you don't want it), length rules, block lists.
  • Classifier (model-based): train a small model on known high-quality text; keep documents that score well. (Llama 3's "model-as-judge" version is in the case study below.)

Why de-duplicate?

  • Repeated text gets memorised by the model (it "mugs it up").
  • It wastes compute — no new learning happens on the 50th copy.
  • It prevents test-set contamination: if benchmark text leaks into training, scores are inflated.
  • How: n-gram / MinHash overlap between documents; can be sentence-level or paragraph-level. (Assignment 1 expects you to try this on your own PDFs.)

Student question from classDetecting PII — regex, classifier, or LLM judge?

A number can be private (a phone number) or harmless (a statistic). The professor's advice: before you use an LLM, ask whether you need one. A heuristic/rule-based filter or a small ML classifier is far cheaper. Llama 3 used an LLM only because it was building a pre-training corpus of trillions of tokens, and even then only to label a sample. An LLM judge also needs careful prompt design and testing.

Worked exampleWhy packing beats padding

Context window = 512 tokens. Three documents: 100, 250 and 150 tokens.

Padding: each document gets its own 512-slot window → \( 3 \times 512 = 1536 \) slots, only \( 500 \) hold real text → 33% useful, 67% wasted compute.

Packing: concatenate doc1 <eos> doc2 <eos> doc3 <eos> = \( 500 + 3 = 503 \) tokens in one window; the last 9 slots are filled by the start of the next document → ≈ 100% useful. The <eos> separator tells the model where one document ends.

Data mixture and curriculum

The whole idea: data is not fed from one pool. Sources (web, code, math, books, multilingual…) are mixed in chosen proportions, and the mix changes over training.

  • Data mixture — what fraction of each source (e.g. more code → better coding).
  • Data curriculum — how the mixture changes across stages: start with easy, general data; later add harder or specialised data (math, code, long documents).
  • Annealing (Llama 3): in the final stage, lower the learning rate to 0 while up-sampling high-quality math and code. Llama 3 8B improved notably on GSM8K/MATH; the 405B model barely changed (it already learns well from the general mix).
  • Long context is a curriculum too: context length was raised gradually, 8K → 128K, in stages.

Scaling laws

The problem

A big pre-training run costs millions of dollars and happens once. Before starting you must choose \( N \) (parameters) and \( D \) (training tokens). Both cost compute:

$$ C \approx 6\,N\,D \ \text{FLOPs (rough estimate for a dense Transformer)} $$

With a fixed budget \( C \), a bigger model gets less data and vice versa. A scaling law is the discovery that loss falls smoothly and predictably as \( N \), \( D \) or \( C \) grows — so you can train small models cheaply, fit the curve, and extrapolate to the big run. (Predictions are estimates, not guarantees. Meta used this to choose Llama 3's data mixtures.)

Analogy — baking for a wedding You can't test a 500-person cake at full scale. You bake small test cakes, note how taste improves as you change the recipe, and extrapolate before committing the ingredients.

Kaplan et al. (2020)

  • Loss follows a power law: \( L \propto X^{-\alpha} \) for \( X \in \{N, D, C\} \). \( \alpha \) is a fitted exponent, small (≈ 0.05–0.1), so returns diminish but are predictable.
  • Counting parameters: each layer has ≈ \( 12 d^2 \) weights (attention \( 4d^2 \) + feed-forward \( 8d^2 \)); multiply by the number of layers.
  • Conclusion: model size matters most. With 10× compute → ~5× bigger model but only ~2× more data (\( 5\times 2 = 10 \)). So industry built huge models on little data: GPT-3 = 175B parameters on 300B tokens ≈ 1.7 tokens/parameter.

Worked exampleDoes GPT-3 really have 175B parameters?

GPT-3: 96 layers, \( d = 12{,}288 \).

Step 1. \( d^2 = 12288^2 = 150{,}994{,}944 \).

Step 2. One layer: \( 12 \times 150{,}994{,}944 \approx 1.81\text{B} \).

Step 3. 96 layers: \( 96 \times 1.81\text{B} \approx 173.9\text{B} \approx 175\text{B}\) ✓ (embeddings add a little more).

Chinchilla (Hoffmann et al., 2022)

  • Kaplan: 10× compute → 5× model, 2× data. Chinchilla: scale both equally → \( \sqrt{10}\approx 3.2\times \) each.
  • Rule of thumb: ~20 training tokens per parameter is compute-optimal (cheapest route to a given loss — not a minimum).
  • Existing giants were under-trained: Chinchilla 70B used the same compute as Gopher 280B and beat it, GPT-3 and MT-NLG.

Worked exampleDesigning a model for a budget (typical exam style)

Question: You have \( C = 10^{24} \) FLOPs. Using \( C = 6ND \) and the Chinchilla rule \( D = 20N \), how big should the model be and how many tokens should it see?

Step 1. Substitute: \( C = 6 N (20N) = 120\,N^2 \).

Step 2. Solve: \( N = \sqrt{10^{24}/120} = \sqrt{8.33\times 10^{21}} \approx 9.1\times 10^{10} \) → ≈ 91B parameters.

Step 3. Tokens: \( D = 20N \approx 1.83\times 10^{12} \) → ≈ 1.8T tokens.

Check: \( 6 \times 91\text{B} \times 1.83\text{T} \approx 10^{24} \) ✓.

Scaling laws today

A scaling law: spend more of X → Y improves smoothly, usually a straight line on a log scale. The method (small experiments, then extrapolate) now plans thinking and RL spend, not just model size.

Why train an 8B model on 15T tokens?Chinchilla-optimal ≠ best for you

Chinchilla minimises training cost. But a model is trained once and served millions of times. Over-training a small model (1,900 tokens/param instead of 20) costs more to train yet gives a cheaper-to-run model of similar quality.

Catastrophic forgetting

Exam trapWhy mix in general data when continuing pre-training?

When a network learns new data, the weight updates can overwrite what it learned before — worst when the new data is a different distribution. If you continue Llama 3 only on finance text, finance improves but general knowledge, coding and instruction-following drop ("it will forget who the Prime Minister of India is"). This is related to overfitting: it mugs up the recent data. Mitigation by mixing general tokens in.

MitigationIdeaNotes
Replay (data mixing)Mix a share of original general data into new dataMost effective, standard. ~5% often enough; FinLLaMA used ~25%
LR scheduleRe-warm to peak LR, then decayHigher LR learns faster but forgets more — pair with replay
LoRA / PEFTFreeze base weights, train small adaptersForgets less but also learns less new knowledge; best for fine-tuning (next session)

Worked exampleA 3 : 1 mixture

You have a budget of 80B tokens for CPT with finance : general = 3 : 1. Finance = \( 80 \times 3/4 = 60\text{B} \); general = \( 80\times 1/4 = 20\text{B} \). Every batch should contain roughly one general example for every three finance examples.

Other points from Q&A: if your domain has special words not in the tokenizer, you can extend the vocabulary; fine-tuning changes the weights and embeddings (all components are updated in full continued pre-training).

Learning-rate schedule for continued pre-training

  • Warm-up: start small, ramp up, so the first updates (with fresh optimizer statistics) don't destabilise training.
  • Cosine decay: lower the LR gradually so the model settles into a good solution; training stops when updates become negligible.
  • Why re-warm? At the end of pre-training the LR is ≈ 0, so the model can barely learn a new domain unless you raise it again.
Memorise — the CPT recipe Re-warm the LR to its peak → re-decay (repeat the original schedule) → add replay of general data. Together these can match retraining from scratch at a fraction of the cost.

Model-as-judge data filtering

  1. Web data → clean, de-duplicate, safety-filter.
  2. Llama 2 labels a sample of documents high / low quality.
  3. Train cheap classifiers on those labels — fastText (fast) and DistilRoBERTa (better).
  4. Classifiers score the entire web corpus → keep the high-quality part.

Why not run Llama 2 on everything? Too costly over trillions of tokens, so the big model labels a sample and small classifiers do the bulk work.

Student question from class"30T training tokens but only 4K context — how?"

Context length ≠ dataset size. The model reads 4,096 tokens per sequence; the 30T tokens are cut into sequences and processed in batches over many steps. Roughly \( 30\times10^{12}/4096 \approx 7.3 \) billion sequences. Larger context just lets the model take more input at once — that's why chatbots now accept many documents.

Emergent abilities

Analogy — water turning to ice Cool water slowly and nothing seems to change… until at 0 °C it suddenly freezes. "Emergent" abilities look similar: random-level performance until some scale, then a jump.
  • Definition: an ability is emergent if it is absent in smaller models but present in larger ones — it can't be predicted by extrapolating from small models. Features claimed: sharpness (appears seemingly instantly) and unpredictability.
  • Counter-view (Schaeffer et al., 2023 — "Are Emergent Abilities a Mirage?"): the jumps can vanish with different metrics or better statistics — so emergence may not be a fundamental property of scaling.
CapabilityWhat it isNote
In-context learning (GPT-3, 2020)Instruction and/or few examples in the prompt; the model continues the textNo gradient updates — weights unchanged
Instruction followingFine-tuning on diverse instruction–response pairsDepends on data and post-training, not size alone
Step-by-step reasoning (chain-of-thought)Generate intermediate steps for multi-step problemsEarly gains seen ~60–100B parameters, not a universal threshold; small models like Qwen3-4B/8B reason well via targeted training, RL and distillation

Memorise — Session 2 on one card Pre-train = self-supervised next-token prediction (CLM) on trillions of tokens; loss = cross-entropy, perplexity = \( e^{\mathcal L} \). Data: filter → de-dup → remove PII → tokenize + pack; then mix & curriculum, anneal at the end. Self-check

Q1. Why does the LM head multiply by \( E^{\top} \), and what is its shape?
The hidden state is \( 1\times d \) but we need one logit per vocabulary word, \( 1\times |V| \). So we need a \( d\times|V| \) matrix. Reusing the input embedding table transposed (weight tying) avoids a second big matrix and keeps each token's meaning consistent on input and output. Llama 3 8B: \( 4096\times128000 \approx 525 \)M parameters.
Q2. Why do modern LLMs use causal LM instead of masked LM?
Next-token prediction trains the exact skill needed for text generation — writing left to right. MLM sees context on both sides, which is good for understanding but doesn't teach generation directly.
Q3. Name three reasons to de-duplicate pre-training data.
(1) Prevents memorisation of repeated text; (2) saves compute that would be wasted on repeated tokens; (3) prevents test-set contamination that inflates benchmark scores. Method: n-gram / MinHash overlap.
Q4. You have \( C = 6\times10^{23} \) FLOPs. Chinchilla-optimal \( N \) and \( D \)?
\( 120N^2 = 6\times10^{23} \Rightarrow N^2 = 5\times10^{21} \Rightarrow N \approx 7.07\times10^{10} \approx 71\text{B} \). \( D = 20N \approx 1.41\text{T} \) tokens. (This is Chinchilla's own size: 70B on 1.4T.)
Q5. You continue pre-training Llama 3 only on legal text and it forgets how to code. What happened and how do you fix it?
Catastrophic forgetting: weight updates for the new distribution overwrote older knowledge. Fix: replay — mix in general (and code) data, e.g. 3:1 legal:general; use the re-warm + re-decay LR schedule; or use LoRA/PEFT adapters if fine-tuning.
Q6. Why was Llama 3 8B trained on ~1,900 tokens per parameter when Chinchilla says 20?
Chinchilla minimises training cost for a given loss. A model is served many more times than it is trained, so spending extra training compute to get a small, cheap-to-run model of the same quality is a good trade.
Q7. Why is a base model's answer to "What is the capital of France?" often another question?
Pre-training only teaches it to continue text; in its training data such a question is often followed by more quiz questions. Post-training (SFT / instruction tuning, then preference alignment) teaches it to answer.
