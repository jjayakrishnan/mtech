Session 9 · Agentic AI Frameworks 10 marks

Likely Question

Explain the ReAct (Reason + Act) loop used by autonomous LLM agents, naming its three core steps and how the loop terminates. Then compare LangChain, CrewAI, and AutoGen as agentic frameworks in tabular form, and state which one you would pick for a given multi-agent scenario.

a. Explain the ReAct loop with a diagram and a worked trace. 4 marks

b. Compare LangChain vs CrewAI vs AutoGen in a table and justify a framework choice for a scenario. 6 marks

How to structure the answer

Don't just draw the loop — name the three steps in order, show one full worked cycle, and say explicitly how the agent knows to stop. For the table, examiners reward a differentiator per row over vague adjectives: instead of "CrewAI is simpler," say why (fixed role/task abstraction vs. a general-purpose graph you must design yourself).

9a · The ReAct Loop: Thought → Action → Observation

Think of a detective solving a case with no fixed script. She doesn't silently think through the whole case and announce a verdict (that's plain chain-of-thought reasoning — all in her head, ungrounded). Instead she works in short bursts: form a hypothesis about what to check next (Thought), go check it — interview a witness, examine a record (Action), read what came back (Observation), and only then form her next hypothesis. She repeats this cycle, each round grounded in real evidence, until she has enough to close the case. That loop — reason, act on the world, observe the result, reason again — is exactly the ReAct pattern (Yao et al., 2022) that autonomous LLM agents use.

The three steps, precisely
  • Thought — the model's internal reasoning, in natural language: what do I know so far, what's missing, what should I do next? It is never executed — it only decides the next Action.
  • Action — a structured call to an external tool chosen by the Thought, e.g. Search[query], Calculator[expr], an API call, or a code-execution call.
  • Observation — the real result returned by that tool, appended to the model's context. It is not generated by the model — it comes from the outside world, which is what grounds the next Thought in fact rather than hallucination.

The loop repeats — Thought2 is conditioned on Observation1, and so on — until a Thought concludes "I have enough evidence," at which point the agent emits a terminal Finish[answer] instead of another tool call.

Worked trace — a classic multi-hop ReAct example (in the style of Yao et al.'s HotpotQA demonstrations):

Q: What is the elevation of the tallest mountain in the country that hosted the 2016 Summer Olympics? Thought 1: I need to find which country hosted the 2016 Olympics. Action 1: Search[2016 Summer Olympics host country] Observation 1: Brazil. Thought 2: Now I need the tallest mountain in Brazil. Action 2: Search[tallest mountain in Brazil] Observation 2: Pico da Neblina. Thought 3: Now I need the elevation of Pico da Neblina. Action 3: Search[Pico da Neblina elevation] Observation 3: 2,995 metres. Thought 4: I have host country, mountain, and elevation — no further search is needed. Action 4: Finish[2,995 metres]
Common mistake

Writing the cycle out of order (e.g. "Action, then Thought, then Observation") or describing ReAct as "just chain-of-thought prompting." Plain chain-of-thought never touches the real world — it reasons in one unbroken block and can hallucinate a fact halfway through with nothing to correct it. ReAct's Observation is a genuine, external, unpredictable result; that grounding is the entire point and is worth stating explicitly for marks.

Memorise

Thought → Action → Observation, repeat, then Finish[answer]. Thought never touches the world; Action does; Observation is what the world sends back.

9b · LangChain vs CrewAI vs AutoGen

All three let an LLM call tools and (with extra setup) coordinate several agents, but they start from different mental models: LangChain gives you a general toolbox and, via LangGraph, an explicit state graph you wire up yourself; CrewAI gives you a fixed "team" abstraction (roles, goals, tasks) with almost no wiring; AutoGen treats multi-agent systems as a conversation between agents, with a first-class ability to write and execute code.

Worked example — applying the table to a scenario

Scenario: "Build a 3-agent pipeline — a Researcher gathers information, a Writer drafts a report, an Editor reviews it — with minimal setup time."

Pick CrewAI. The scenario is exactly CrewAI's native abstraction: three named roles with clear goals, handed off sequentially. LangGraph could do it too, but you'd hand-wire the graph nodes and edges yourself for no extra benefit here; AutoGen's conversational/code-execution strengths aren't needed since no agent is executing or debugging code. Stating why the other two are a worse fit, not just naming the right one, is what earns full marks on a justify-your-choice question.

Common mistake

Claiming "LangChain doesn't support multi-agent orchestration." It does — via LangGraph — it's just not a bundled, opinionated abstraction the way CrewAI's Crew or AutoGen's GroupChat are. Say "more effort to wire up," not "can't do it."

Try it yourself

Name one advantage AutoGen has over CrewAI when an agent needs to write and debug Python code, and explain why.

AutoGen has a native, sandboxed code-execution agent: generated code is actually run, and its stdout/stderr is fed back automatically as the next Observation, so the agent can see its own error and retry — a built-in ReAct-style debug loop. CrewAI has no equivalent first-class capability; you would have to hand-write a custom Tool that wraps a code interpreter and manually pipes the output back into the task context.
