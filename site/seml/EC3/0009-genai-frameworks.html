The GenAI Framework Landscape

The jump from "call the OpenAI API" to "build a production agentic system" requires frameworks that handle chaining, memory, tool use, multi-agent coordination, and observability. Three frameworks dominate the SEML syllabus:

FrameworkPrimary abstractionBest for
LangChain / LangGraphChains, agents, tools, memoryFlexible single-agent or graph-based multi-agent apps
CrewAICrew, Role, Task, ProcessTask-assigned multi-agent teams with clear role boundaries
AutoGenConversableAgent, GroupChatConversational multi-agent loops with human-in-the-loop
Analogy — Staffing models

LangChain is like hiring a versatile contractor — you define exactly what they do. CrewAI is like hiring a specialist team (researcher + writer + editor) where each member has a defined role. AutoGen is like a group chat where any participant (including a human) can jump in. The choice depends on how structured your task is.

LangChain & LCEL

LangChain components
  • LLMs / ChatModels — the underlying AI model (OpenAI, Anthropic, etc.)
  • Prompts — PromptTemplate, ChatPromptTemplate, few-shot examples
  • Chains — composed sequences of components
  • Memory — conversation history (BufferMemory, SummaryMemory)
  • Tools — callable functions an agent can invoke (search, calculator, API)
  • Retrievers — fetch relevant documents for RAG
  • Agents — LLM that decides which tool to call next

LCEL — LangChain Expression Language

LCEL lets you compose chains using the pipe operator |. Each component's output becomes the next component's input:

# Build a RAG chain in LCEL
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_template(
  "Answer using context: {context}\n\nQuestion: {question}"
)

chain = retriever | prompt | ChatOpenAI() | StrOutputParser()

result = chain.invoke({"question": "What are Q3 revenue drivers?"})

Each | step is lazy — nothing runs until .invoke() is called. LCEL chains are also automatically streamable and traceable with LangSmith.

LangGraph for multi-agent

LangGraph extends LangChain by representing agent workflows as directed graphs. Nodes are agents (or functions), edges are transitions. You can add conditional edges (routing logic) and cycles (the agent loop). This makes LangGraph the right tool for complex multi-agent workflows where agents need to re-visit steps or branch on conditions.

The ReAct Agent Loop

ReAct = Reason + Act

ReAct is a prompting strategy (and the underlying loop for most LangChain agents) where the LLM alternates between Thought (reasoning about the current situation), Action (choosing a tool call), and Observation (receiving the tool's output). This loop repeats until the agent decides it has enough information to give a final answer.

The loop expressed formally:

  1. Thought: LLM reasons about what it knows and what it needs. Produces internal reasoning text.
  2. Action: LLM outputs a structured tool call (e.g., search("Q3 revenue BITS")).
  3. Observation: The framework runs the tool and gives the LLM the result.
  4. Repeat from 1 until LLM produces a Final Answer.
ReAct vs Chain-of-Thought

Chain-of-Thought (CoT) only adds a Thought step — the model reasons but takes no actions, so it cannot retrieve external information. ReAct adds Action + Observation on top of CoT, making the agent grounded in real data. Exam question: "How does ReAct improve over CoT?" — the key is the ability to call tools and observe results.

ReAct prompt format

Question: What is BITS Pilani's founding year?
Thought: I should search for this fact.
Action: search("BITS Pilani founding year")
Observation: BITS Pilani was founded in 1964.
Thought: I now have the answer.
Final Answer: BITS Pilani was founded in 1964.

CrewAI

Key CrewAI concepts
  • Agent — has a role, goal, backstory, and optional tools. Each agent is specialised.
  • Task — a unit of work with a description and expected_output. Assigned to an agent.
  • Crew — the collection of agents + tasks + process type.
  • Process — Sequential (tasks in order) or Hierarchical (a manager LLM delegates to workers).

Worked Example: Research Crew

from crewai import Agent, Task, Crew, Process

researcher = Agent(
  role="Senior Research Analyst",
  goal="Find accurate market data",
  tools=[search_tool, scrape_tool]
)

writer = Agent(
  role="Technical Writer",
  goal="Write clear, concise reports"
)

research_task = Task(
  description="Research Q3 revenue trends in SaaS",
  expected_output="Bullet points with sources",
  agent=researcher
)

write_task = Task(
  description="Write a 500-word report from research",
  agent=writer, context=[research_task]
)

crew = Crew(agents=[researcher, writer], tasks=[research_task, write_task],
           process=Process.sequential)
result = crew.kickoff()
Hierarchical process

In Process.hierarchical, CrewAI creates a manager agent that reads all task descriptions and decides which agent to delegate to and in what order. The manager is itself an LLM call. This is analogous to the Saga orchestration pattern — the manager is the orchestrator.

AutoGen

AutoGen (Microsoft) centres on ConversableAgent — an agent that can send and receive messages, call tools, and optionally involve a human. Agents talk to each other via a structured chat protocol.

AutoGen agent types
  • ConversableAgent — base type; can be LLM-backed or rule-based
  • AssistantAgent — LLM-backed, designed to help complete tasks
  • UserProxyAgent — represents a human; can auto-execute code or prompt for human input
  • GroupChat — orchestrates multiple agents in a round-robin or speaker-selection conversation
from autogen import AssistantAgent, UserProxyAgent

assistant = AssistantAgent("assistant", llm_config={"model": "gpt-4o"})
user = UserProxyAgent("user_proxy", human_input_mode="NEVER",
                        code_execution_config={"work_dir": "./code"})

user.initiate_chat(assistant, message="Write a Python function for linear regression")
# AutoGen: assistant generates code → user_proxy executes it → result fed back
Key AutoGen differentiator

AutoGen's UserProxyAgent with human_input_mode="ALWAYS" enables genuine human-in-the-loop: a person can redirect the conversation at each step. This is the killer feature for enterprise use cases where full automation is risky (e.g., financial workflows, compliance).

The instructor's mental model

In Session 9, the instructor framed the evolution as: "MLOps → LLMOps → AgentOps." LangChain is the LLMOps-era framework. CrewAI and AutoGen are AgentOps-era. The patterns from Session 8 (Saga, Blackboard, Orchestration) are implemented differently in each framework — LangGraph = orchestration-based Saga; CrewAI sequential = choreography; AutoGen GroupChat = blackboard-like shared context.
