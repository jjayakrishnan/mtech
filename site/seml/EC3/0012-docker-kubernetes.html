Why Containers for ML?

Analogy — Shipping container

Before standardised shipping containers, every port unloaded goods differently — cranes, pallets, ropes. The standardised container changed everything: the same box fits any ship, any crane, any truck. Docker does the same for software: your ML model and all its dependencies are packed into a standard container that runs identically on your laptop, the CI server, or a cloud GPU cluster.

ML-specific problems that containers solve:

  • "Works on my machine" syndrome — different CUDA versions, Python versions, library conflicts
  • Reproducibility — the exact environment used for training can be used for inference
  • Isolation — multiple models with conflicting dependencies run in separate containers
  • Scalability — Kubernetes can spin up 100 identical model-serving containers in seconds

Docker Fundamentals

Key Docker concepts
  • Image — read-only template for a container. Defined by a Dockerfile. Layers are cached.
  • Container — a running instance of an image. Has a writable top layer.
  • Registry — stores images. Docker Hub is public; ECR (AWS), GCR (Google), ACR (Azure) are private.
  • Layer — each Dockerfile instruction adds a layer. Layers are immutable and shared between images that share common base layers.
  • Volume — persistent storage mounted into a container. Survives container restarts.
Container vs image — exam distinction

An image is a blueprint (read-only). A container is a running instance of that blueprint. You can run many containers from one image. When a container stops, its writable layer is lost (unless you commit it or use volumes). Students often confuse these — be precise in exam answers.

Dockerfile Walkthrough

A Dockerfile for a FastAPI ML model server:

# Layer 1: base image (FROM)
FROM python:3.11-slim

# Layer 2: working directory
WORKDIR /app

# Layer 3: install deps (copy requirements first — cache this layer!)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Layer 4: copy application code
COPY src/ .

# Layer 5: copy model artefact
COPY models/classifier.pkl models/

# Metadata: which port the server listens on
EXPOSE 8080

# Default command to run
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]
Layer caching optimisation

Copy requirements.txt and run pip install before copying your source code. Dependencies change rarely; source code changes often. This way, the expensive pip install layer is cached on subsequent builds as long as requirements.txt hasn't changed. A common beginner mistake is COPY . . first — invalidating the cache on every code edit.

Key Dockerfile instructions

InstructionPurposeExample
FROMBase image (must be first)FROM python:3.11-slim
WORKDIRSet working directory for subsequent instructionsWORKDIR /app
COPYCopy files from host to imageCOPY src/ /app/src/

Docker Compose

Docker Compose defines and runs multi-container applications in a single YAML file. Example: a model server + Redis cache + monitoring sidecar:

version: "3.9"
services:
  model-server:
    build: .
    ports: ["8080:8080"]
    environment:
      REDIS_URL: redis://redis:6379
    depends_on: [redis]

  redis:
    image: redis:7-alpine
    volumes: ["redis_data:/data"]

  monitor:
    image: prom/prometheus:latest
    ports: ["9090:9090"]

volumes:
  redis_data:

Run with: docker compose up --build. All services start together; the network is auto-created so services discover each other by name (e.g. redis:6379).

Kubernetes

Kubernetes key concepts
  • Cluster — one or more machines (nodes) managed by Kubernetes
  • Node — a machine (VM or bare metal) in the cluster; runs pods
  • Pod — the smallest deployable unit; one or more containers sharing a network and storage
  • Deployment — declares desired state (how many replicas of a pod); manages rolling updates
  • Service — stable network endpoint for a set of pods (load balances across pod replicas)
  • Ingress — HTTP routing rules to expose services externally
  • ConfigMap / Secret — inject configuration or credentials into pods
  • PersistentVolume (PV) — durable storage that outlives a pod
Analogy — Docker : Kubernetes :: Container : Shipping port

Docker is the shipping container. Kubernetes is the entire port system — cranes (scheduler), berths (nodes), customs (RBAC), and traffic control (services/ingress). You don't manage individual containers in Kubernetes; you declare desired state and the system maintains it.

Deployment YAML anatomy

apiVersion: apps/v1
kind: Deployment
metadata:
  name: model-server
spec:
  replicas: 3 # run 3 copies
  selector:
    matchLabels: {app: model-server}
  template:
    metadata:
      labels: {app: model-server}
    spec:
      containers:
      - name: model-server
        image: myregistry/model-server:v1.2
        ports: [{containerPort: 8080}]
        resources:
          requests: {cpu: "500m", memory: "512Mi"}
          limits: {cpu: "2", memory: "2Gi"}
        livenessProbe:
          httpGet: {path: /health, port: 8080}

MiniKube for local development

MiniKube runs a single-node Kubernetes cluster on your laptop. Use it to test Kubernetes manifests before deploying to production. Key commands: minikube start, minikube dashboard (opens web UI), minikube service model-server --url (get local URL for a service). The instructor used MiniKube in the session demo for deploying a containerised LLM agent.

Exam Prep

High-probability exam questions
  • What is a Docker image vs a container? How do layers work?
  • Explain the layer caching optimisation in a Dockerfile. Why copy requirements.txt before source code?
  • What is a Kubernetes Deployment? What does replicas: 3 mean?
  • What is the difference between a Kubernetes Service and a Pod?
  • What is MiniKube used for?
QuestionOne-line answer
Image vs container?Image = read-only blueprint (Dockerfile). Container = running instance with writable top layer.
Why COPY requirements first?Dependencies change rarely; source changes often. Reorder avoids re-running expensive pip install on every code change.
Pod vs Deployment?Pod = one or more containers. Deployment = manages pod replicas, rolling updates, rollback.
Service purpose?Stable DNS name + load balancer for a set of pods. Pods are ephemeral; Service IP is stable.
EXPOSE vs -p flag?EXPOSE documents the port (metadata). -p 8080:8080 at run time actually publishes it on the host.
