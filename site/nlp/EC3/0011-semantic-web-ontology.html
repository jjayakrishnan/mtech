1 · The Problem: Computers Don't Understand Meaning

Analogy

"My mouse is broken. I need a new one." — A human knows you mean the computer peripheral. A computer sees: {my, mouse, is, broken}. The syntactic web — HTML documents linked by hyperlinks — is great for humans but opaque to machines.

Tim Berners-Lee invented the World Wide Web in 1991. By 1998 (Google's founding), the web was purely syntactic: documents rendered for humans, with no machine-readable semantics. Computers could present pages but not understand them.

What Machines Can't Do on the Syntactic Web

  • Answer: "Find animals that use sonar but aren't bats or dolphins"
  • Answer: "What were the most popular songs when Obama was elected?"
  • Integrate data from two different databases (different field names, different schemas)
  • Determine that "bank" in Dataset A and "banque" in Dataset F are the same thing

2 · The Semantic Web Vision

Definition

The Semantic Web is an extension of the World Wide Web where data is given explicit, machine-readable meaning. The vision: a "Web of Data" where computers can query, integrate, and reason over information across websites — like a giant global database.

Semantic Web Layer Cake

TrustSignatures, ProvenanceVerify data authenticity

3 · RDF — Resource Description Framework

Core Concept

RDF models knowledge as triples: \(\langle \text{Subject}, \text{Predicate}, \text{Object} \rangle\). Each part is a URI (Uniform Resource Identifier) — a globally unique name for the resource.

Triple Examples

-- "The Glass Palace" was written by Amitav Ghosh in 2000 <http://isbn/000651409X> dc:title "The Glass Palace" <http://isbn/000651409X> dc:creator <http://author/ghosh> <http://isbn/000651409X> dc:date "2000" <http://author/ghosh> foaf:name "Ghosh, Amitav" <http://author/ghosh> foaf:homepage <http://www.amitavghosh.com>

RDF Graph

A set of RDF triples forms a directed labelled graph:

  • Nodes: URIs (resources) or literals (strings, numbers)
  • Edges: Predicates (URIs naming the relationship)
  • Blank nodes: anonymous resources without a URI

RDF Serialization Formats

FormatDescriptionFile Extension
Turtle (.ttl)Compact, human-readable. Prefix shortcuts..ttl
N-TriplesOne triple per line. Machine-friendly..nt
RDF/XMLXML-based. W3C original format. Verbose..rdf
JSON-LDJSON format. Web-developer friendly..jsonld

Turtle Example

@prefix dc: <http://purl.org/dc/elements/1.1/> . @prefix foaf: <http://xmlns.com/foaf/0.1/> . <http://isbn/000651409X> dc:title "The Glass Palace" ; dc:creator <http://author/ghosh> ; dc:date "2000" . <http://author/ghosh> foaf:name "Ghosh, Amitav" ; foaf:homepage <http://www.amitavghosh.com> .
Key Insight: Data Integration

When French bookstore dataset F and English dataset A both use <http://isbn/000651409X> as the URI for the same book, they can be automatically merged. Same URI = same thing. This is the "Linked" in Linked Data.

4 · OWL — Web Ontology Language

What Is an Ontology?

An ontology is a formal, explicit specification of a shared conceptualization: the classes, properties, and relationships that exist in a domain, plus axioms that constrain their use. In knowledge representation: ontology = shared vocabulary + formal semantics.

RDFS vs OWL

FeatureRDFSOWL DLOWL Full
Classes & subclasses✓✓✓
Properties & domains/ranges✓✓✓
Cardinality constraints✗✓✓
owl:disjointWith✗✓✓
owl:equivalentClass✗✓✓
Decidable reasoning✓✓✗

OWL Key Constructs

-- Classes owl:Class — defines a class (set of individuals) owl:subClassOf — A ⊆ B (every A is a B) owl:equivalentClass — A ≡ B (exactly the same individuals) owl:disjointWith — A ∩ B = ∅ -- Properties owl:ObjectProperty — relates two individuals owl:DatatypeProperty — individual → literal value owl:FunctionalProperty — each subject has ≤1 value owl:InverseOf — hasPart ←→ isPartOf -- Cardinality owl:minCardinality owl:maxCardinality owl:exactly

Ontology Example: Book Domain

5 · SPARQL — Query Language for RDF

What Is SPARQL?

SPARQL (SPARQL Protocol and RDF Query Language) is to RDF what SQL is to relational databases. It queries RDF graphs by matching graph patterns.

Basic SPARQL Query

PREFIX dc: <http://purl.org/dc/elements/1.1/> PREFIX foaf: <http://xmlns.com/foaf/0.1/> SELECT ?title ?authorName WHERE { ?book dc:title ?title . ?book dc:creator ?author . ?author foaf:name ?authorName . FILTER (?title = "The Glass Palace") }

SPARQL Query Types

TypeReturnsUse Case
SELECTTable of variable bindingsRetrieve specific values
ASKBoolean (true/false)Test if pattern exists
CONSTRUCTNew RDF graphTransform/extract subgraph
DESCRIBERDF description of a resourceExplore unknown resources
Complex Query: "Songs popular when Obama was elected"
SELECT ?song, COUNT(?vote) AS ?likes FROM <WorldWideWeb> WHERE { ?vote inFavourOf ?song . ?vote madeAt ?date . Obama electedAt ?date . } ORDER BY DESC(?likes)

This query spans multiple datasets — only possible because everything is RDF with shared URIs.

6 · Knowledge Graphs

Definition

A Knowledge Graph is a graph-structured knowledge base where facts are stored as entity–relation–entity triples. Modern KGs combine RDF-style triples with graph database technology and ML-based embedding models.

Major Knowledge Graphs

KGSizeCreatorUse Case
Freebase / Wikidata50B+ factsGoogle / WikimediaOpen, collaborative, multilingual
Google Knowledge Graph500B+ factsGoogleSearch enhancement, entity cards
DBpedia4.6M entitiesOpen sourceStructured version of Wikipedia
YAGO10M entitiesMPIWikipedia + WordNet + GeoNames

Ontology Learning

Building ontologies by hand is expensive. Ontology learning automates this:

  • Term extraction: Find domain terms from text
  • Synonym detection: NLP clustering, lexical patterns
  • Hierarchy induction: Hearst patterns — "X such as Y" → Y is-a X
  • Relation extraction: "Amitav Ghosh wrote The Glass Palace" → (Ghosh, wrote, GlassPalace)

7 · Linked Open Data (LOD)

Linked Open Data applies Semantic Web standards to publicly available datasets, forming the LOD Cloud — a global interconnected dataset.

Tim Berners-Lee's 5-Star LOD

★LevelRequirement
★AvailableMake data available on the web under an open license
★★StructuredAvailable as machine-readable structured data (e.g., Excel)
★★★Open formatNon-proprietary format (e.g., CSV, not Excel)
★★★★URIUse URIs to denote things (identify resources on the web)
★★★★★LinkedLink to other people's data to provide context
Exam Note

The key difference between the syntactic web and semantic web: the syntactic web links documents; the semantic web links data/concepts. DBpedia, Wikidata, and GeoNames are the hubs of the LOD cloud.

9 · Practice Questions

Q1 · What is an RDF triple? Give an example.

An RDF triple is a statement in the form ⟨Subject, Predicate, Object⟩. Each part is a URI (or a literal for the object). Example:
⟨<http://isbn/000651409X>, dc:creator, <http://author/ghosh>⟩
This states: "The Glass Palace (identified by its ISBN URI) was created by Amitav Ghosh (identified by his author URI)."

Q2 · Explain the difference between RDFS and OWL.

RDFS (RDF Schema) provides basic vocabulary for class hierarchies and property declarations: subClassOf, domain, range. It's simple but limited — no cardinality, no disjointness, no equivalence.
OWL (Web Ontology Language) adds: cardinality (min/max/exact), owl:disjointWith, owl:equivalentClass, owl:FunctionalProperty, owl:InverseOf, and full description logic semantics. OWL DL ensures decidable reasoning; OWL Full is undecidable but more expressive.

Q3 · What are the 5 stars of Linked Open Data?

★ Open license on the web; ★★ Machine-readable structured data (Excel); ★★★ Non-proprietary format (CSV); ★★★★ Use URIs to identify things; ★★★★★ Link your URIs to other datasets. Each star adds a level of interoperability. 5-star LOD enables automatic data integration across the web.

Q4 (6-mark) · Explain how the Semantic Web enables data integration. Use the book dataset example.

Problem: English bookstore A and French bookstore F have data about the same book (The Glass Palace) in different schemas (different field names, different languages). Syntactic web: impossible to auto-merge — no common reference point.
Solution — Semantic Web:
1. Both datasets export data as RDF triples using globally unique URIs.
2. Both use the ISBN URI <http://isbn/000651409X> for the same book.
3. When two triples share the same subject URI, their information is automatically merged into one RDF graph.
4. A SPARQL query can now retrieve title (from A), translator (from F), and author details in one query across both datasets.
Key principle: "Same URI = same thing" — URIs enable cross-dataset identity resolution that SQL databases or HTML pages cannot provide.
