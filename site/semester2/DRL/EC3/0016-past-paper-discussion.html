Q1 — Multi-Armed Bandit: Healthcare Treatment 10 marks

EC-3Question 1 — Context
A healthcare system chooses between two treatments each round:
T = Tumor ablation, past rewards: +1, +1, −1, −1 (N=4)
M = Medication, past rewards: +1, −1, +1, r (N=4)
t = 8 rounds elapsed. UCB constant c. Q₀ = 0 for all actions.

(a) Compute Q-values using sample average 2 marks

Answer Sample-average estimator: \( Q(a) = \frac{1}{N(a)}\sum_i R_i(a) \)

\[ Q(T) = \frac{(+1)+(+1)+(-1)+(-1)}{4} = \frac{0}{4} = 0 \]

\[ Q(M) = \frac{(+1)+(-1)+(+1)+r}{4} = \frac{1+r}{4} \]

(b) Greatest integer r so UCB selects T next 2 marks

Answer UCB score: \( \text{UCB}(a) = Q(a) + c\sqrt{\dfrac{\ln t}{N(a)}} \)

Since \(N(T)=N(M)=4\) and \(t=8\), the exploration bonus is identical for both actions. UCB selects T only when \(Q(T) > Q(M)\):

\[ 0 > \frac{1+r}{4} \;\Longrightarrow\; r < -1 \]

The greatest integer satisfying \(r < -1\) is \(\boxed{r = -2}\).

"The greatest integral value could be −2. Since both actions have been selected equally many times, whichever has the higher Q value gets picked. Since Q(T) = 0, we need Q(M) < 0, so (1+r)/4 < 0, giving r < −1. The largest integer below −1 is −2."

(c) Non-stationary ERWA update for Q(M) with α = 0.5 3 marks

Answer — Step by step

Exponential recency-weighted average: \(Q_{n+1} = Q_n + \alpha(R_n - Q_n)\). Initialize \(Q_1(M)=0\).

Reward \(r_1=+1\): \(Q_2 = 0 + 0.5(1-0) = 0.5\)
Reward \(r_2=-1\): \(Q_3 = 0.5 + 0.5(-1-0.5) = 0.5 - 0.75 = -0.25\)
Reward \(r_3=+1\): \(Q_4 = -0.25 + 0.5(1-(-0.25)) = -0.25+0.625 = 0.375\)
Reward \(r_4=r\): \(Q_5 = 0.375 + 0.5(r - 0.375) = 0.1875 + 0.5r\)

With \(r=-2\): \(Q_5(M) = 0.1875 + 0.5(-2) = \mathbf{-0.8125}\)

(d) Compare sample average vs ERWA 3 marks

Answer
PropertySample AverageERWA (α=0.5)
Formula\(\frac{1}{n}\sum R_i\)\(Q + \alpha(R-Q)\)
Stationarity assumedYesNo
Weight of older rewardsEqual to recentExponentially decaying
Q(M) with r=−2\((1-1+1-2)/4 = -0.25\)\(-0.8125\)
Why different?All 4 rewards weighted equallyRecent bad reward pulls estimate down more
"The simple average treats all rewards equally — it doesn't care whether it happened long ago or just now. The ERWA with α=0.5 gives recent rewards more weight, so when the most recent reward is very negative, the estimate falls sharply. This is why ERWA is preferred in non-stationary environments like dynamic healthcare outcomes."
🧠 Memorise — ERWA vs Sample Average

Sample average \(= \frac{1}{n}\sum R_i\) — good for stationary; all rewards equally weighted.

ERWA \(Q_{n+1} = Q_n + \alpha(R_n - Q_n)\) — good for non-stationary; recent rewards count more (weight \(\alpha(1-\alpha)^k\) on reward k steps back).

With α=0.5 and r=−2: ERWA → −0.8125 (sharper drop) vs. sample average → −0.25 (gentler).

Q2 — Robot Warehouse MDP 10 marks

EC-3Question 2 — Context
States: H=High, M=Medium, L=Low battery; T=terminal. Actions: C=Continue, R=Recharge. γ=0.9.
From M with C: P(M|M,C)=0.6, P(L|M,C)=0.4, r=+1 for both transitions.
From M with R: P(H|M,R)=1, r=−2.
Policy π₀: Continue everywhere. Given initial values: V₀(H)=8, V₀(M)=5, V₀(L)=−10.

(a) V_π(M) using Bellman expectation equation 3 marks

Answer

With \(\pi(C|M)=1\), the Bellman expectation equation for state M:

\[ V_\pi(M) = \sum_{s'} P(s'|M,C)\bigl[R + \gamma V_\pi(s')\bigr] \]

\[ = 0.6\bigl[1 + 0.9 \cdot V_\pi(M)\bigr] + 0.4\bigl[1 + 0.9 \cdot V_\pi(L)\bigr] \]

Using initial estimate \(V_\pi(M) = V_\pi(L) = 1\) for one-step evaluation:

\[ V_\pi(M) = 0.6(1+0.9) + 0.4(1+0.9) = 1.0 \times 1.9 = \mathbf{1.9} \]

(b) Policy improvement: Q(M,C) and Q(M,R) 3 marks

Answer — using V₀(H)=8, V₀(M)=5, V₀(L)=−10

\[ Q_{\pi_0}(M,C) = 0.6[1+0.9\times 5] + 0.4[1+0.9\times(-10)] \]

\[ = 0.6(5.5) + 0.4(-8) = 3.3 - 3.2 = \mathbf{0.1} \]

\[ Q_{\pi_0}(M,R) = 1.0[-2+0.9\times 8] = -2 + 7.2 = \mathbf{5.2} \]

Since \(Q(M,R) = 5.2 > Q(M,C) = 0.1\), the improved policy selects Recharge at M:

\[ \pi_1(\text{Recharge} \mid M) = 1 \]

Intuition: recharging incurs a −2 cost now, but transitions to H where V₀=8, giving large discounted payoff (0.9×8=7.2).

(c) First-visit MC return G(M) 2 marks

Answer

Episode: \((M,C,+1,M)\to(M,C,+1,L)\to(L,R,-3,M)\to(M,C,+1,T)\)

First visit to M is at \(t=0\). Discounted return from \(t=0\):

\[ G(M) = 1 + 0.9(1) + 0.9^2(-3) + 0.9^3(1) \]

\[ = 1 + 0.9 - 2.43 + 0.729 = \mathbf{0.199} \]

(d) Off-policy IS with deterministic target policy 2 marks

Answer

Episode from behavior policy b: \((M,C,+1,M)\to(M,R,-2,H)\to(H,C,+2,T)\)

Target policy π is deterministic: \(\pi(C|M)=1\), therefore \(\pi(R|M)=0\).

\[ \rho = \frac{\pi(C|M)}{b(C|M)} \times \frac{\pi(R|M)}{b(R|M)} = \frac{1}{b(C|M)} \times \frac{0}{b(R|M)} = \mathbf{0} \]

ρ = 0 → no update occurs. This episode contributes nothing to the value estimate.

"When the target policy is completely deterministic and takes an action the behavior policy took but the target would never take, the IS ratio becomes zero. In practice, to avoid this degeneracy you should assume a small stochastic probability for all actions in the target policy so that ρ is never exactly zero. This is a key pitfall in off-policy MC with deterministic target policies."
⚠️ Common Mistake — IS with deterministic policy

Students often compute ρ ignoring that π(R|M)=0 for a deterministic policy. If π is deterministic and the behavior policy ever takes an action the target would not, ρ collapses to zero and the episode is discarded. The fix: always check whether the target policy assigns non-zero probability to every action taken in the episode.

Q3 — AI Tutor: Policy Gradient 10 marks

EC-3Question 3 — Context
States: engagement (Engaged E / Disengaging D) × comprehension (Strong S / Partial P / Weak W).
Actions: H=Hard question, M=Medium question.
Coarse coding features: F₁=𝟙[Partial or Strong], F₂=𝟙[Disengaging], F₃=𝟙[Partial AND Disengaging].
Parameters: θ_H = [0.2, 0.1, 0.05]ᵀ, θ_M = [0, 0, 0]ᵀ.

(a) Coarse coding feature vectors 2 marks

Answer

State (P, D) — Partial comprehension AND Disengaging:

\(F_1=1\) (Partial ∈ {P,S}), \(F_2=1\) (Disengaging), \(F_3=1\) (Partial AND Disengaging)

\[ \boldsymbol{\phi}(P,D) = [1,\;1,\;1]^\top \]

State (P, E) — Partial comprehension AND Engaged:

\(F_1=1\) (Partial), \(F_2=0\) (Engaged, not Disengaging), \(F_3=0\) (not both)

\[ \boldsymbol{\phi}(P,E) = [1,\;0,\;0]^\top \]

(b) Compute softmax π(H | (P,D)) 2 marks

Answer

\[ \pi(H|s) = \frac{e^{\boldsymbol{\theta}_H^\top\boldsymbol{\phi}(s)}}{e^{\boldsymbol{\theta}_H^\top\boldsymbol{\phi}(s)} + e^{\boldsymbol{\theta}_M^\top\boldsymbol{\phi}(s)}} \]

At (P,D): \(\boldsymbol{\theta}_H^\top\boldsymbol{\phi} = 0.2+0.1+0.05 = 0.35\)  and  \(\boldsymbol{\theta}_M^\top\boldsymbol{\phi} = 0\).

\[ \pi(H|(P,D)) = \frac{e^{0.35}}{e^{0.35}+e^{0}} = \frac{1.419}{1.419+1} = \frac{1.419}{2.419} \approx \mathbf{0.587} \]

(c) Policy gradient update for θ_H 3 marks

Answer — REINFORCE with baseline

\[ \boldsymbol{\theta}_H \leftarrow \boldsymbol{\theta}_H + \alpha(R-b)\,\nabla\log\pi(H|s) \]

For softmax: \(\nabla\log\pi(H|s) = [1-\pi(H|s)]\,\boldsymbol{\phi}(s)\)

With \(R=+2\), \(b=1\), \(\alpha=0.05\), \(\pi(H|(P,D))\approx 0.587\):

\[ \Delta\boldsymbol{\theta}_H = 0.05 \times (2-1) \times (1-0.587) \times [1,1,1]^\top = 0.05 \times 0.413 \times [1,1,1]^\top \approx [0.021,\;0.021,\;0.021]^\top \]

Updated: \(\boldsymbol{\theta}_H \approx [0.221,\;0.121,\;0.071]^\top\)

"The gradient of the log-softmax is simply (1 − π(H|s)) multiplied by the feature vector. This is a beautiful result: when π(H|s) is already high, the gradient is small and the policy barely updates. When π(H|s) is low, the gradient is large and the policy gets a stronger push toward selecting H. This is the self-regulating property of the softmax."

Answer

(e) Effect of no baseline 2 marks

Answer

Without baseline: \(\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} + \alpha R\,\nabla\log\pi\)

Problem — high variance. When all rewards are positive (e.g., R ∈ {1, 2, 3}), all actions taken in a trajectory are reinforced regardless of quality. The AI tutor increases the probability of every action, even mediocre ones, making learning noisy and slow.

The baseline b (typically the average return) centers updates so only above-average actions are truly reinforced. No baseline = high variance gradient estimator.

🧠 Memorise — Softmax Policy Gradient

Update rule: \(\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} + \alpha(R-b)\nabla\log\pi(a|s)\)

Softmax gradient: \(\nabla\log\pi(H|s) = [1-\pi(H|s)]\,\boldsymbol{\phi}(s)\)

Baseline reduces variance; without it, all actions in the trajectory get reinforced whether good or bad.

Q4 — MCTS, DQN, AlphaGo, Imitation Learning 10 marks

EC-3Question 4 — Context
MCTS node s has 2 actions: a₁ (Q=0.60, N=4) and a₂ (Q=0.65, N=16). Total visits N_total=20.

(a) UCB scores for a₁ and a₂ — which is selected? 2 marks

Answer

Standard UCB (use \(c=1\) if not given; always use natural log):

\[ \text{Score}(s,a) = Q(s,a) + c\sqrt{\frac{\ln N_{\text{total}}}{N(s,a)}} \]

\(\ln(20) \approx 2.996\)

\[ \text{UCB}(a_1) = 0.60 + \sqrt{\frac{2.996}{4}} = 0.60 + \sqrt{0.749} = 0.60 + 0.866 = \mathbf{1.466} \]

\[ \text{UCB}(a_2) = 0.65 + \sqrt{\frac{2.996}{16}} = 0.65 + \sqrt{0.187} = 0.65 + 0.433 = \mathbf{1.083} \]

Select a₁ (UCB 1.466 > 1.083). Despite a₂'s higher mean, a₁'s low visit count gives it a larger exploration bonus.

"If the C value is not provided in the question, please assume it to be 1. Always use natural logarithm (log base e), not log base 10. This is exactly the same UCB formula from Module 1 — nothing different about it in MCTS. Among the two UCB values, whichever has the maximum is the one selected next."

(b) Two DQN techniques that stabilize training 2 marks

Answer — Technique 1: Experience Replay

All transitions \((s,a,r,s')\) stored in a replay buffer. During training, mini-batches are sampled randomly from the buffer.

Why it stabilizes: Consecutive RL transitions are highly correlated (same region of state space). Random sampling breaks this correlation, making gradient updates closer to the i.i.d. assumption of SGD.

Answer — Technique 2: Target Network

A frozen copy of the network weights \(\boldsymbol{w}^-\) is held fixed for thousands of steps. TD targets use \(\boldsymbol{w}^-\); only the online network \(\boldsymbol{w}\) is gradient-updated.

Why it stabilizes: Without a frozen target, the TD target \(r + \gamma\max_{a'}Q(s',a';\boldsymbol{w})\) changes every step — the network chases a moving target, causing divergence. A fixed target network gives stable training labels.

"To manage stability, you have to use an experience replay buffer. It stores transitions and samples are taken from this stored replay buffer. By doing so you break the correlations. Another one — you have a separate target network, which provides you the Q value of states and actions [using frozen weights]."

(c) AlphaGo vs AlphaGo Zero: key training distinction 2 marks

Answer
AlphaGoAlphaGo Zero
Trained on 30M human expert games (SL policy p_σ)Zero human data — starts from random play
SL step bootstraps MCTS; 3 separate networksNo SL step; single dual-head ResNet f_θ(s)→(p,v)
Beat Lee Sedol 4−1 (March 2016)Beat AlphaGo 100−0 in 3 days of training
"AlphaGo uses human expert data and self-supervised learning to extract the human pattern behaviour, and uses that as a starting point. But AlphaGo Zero — in the absence of human data it still can generalise the pattern. There is no supervised learning model at all. That's your distinction: human-seeded vs purely self-play."

(d) BC loss function and failure mode 2 marks

Answer

Behaviour Cloning loss (discrete actions):

\[ \mathcal{L}(\theta) = -\sum_{(s,a^*)\in\mathcal{D}} \log\pi_\theta(a^*|s) \]

Cross-entropy loss — maximize likelihood of expert actions given states.

Failure mode — distribution shift: BC trains only on expert states. At test time, small learner errors compound: the learner visits states the expert never encountered → policy has no guidance there → errors compound → \(O(\varepsilon T^2)\) cumulative error over horizon T.

(e) How DAgger fixes distribution shift 2 marks

Answer — DAgger (Dataset Aggregation)
Train initial policy π on expert dataset D₀.
Roll out the learner's own policy to collect states the learner actually visits.
Query the expert for correct action labels on those learner-visited states.
Aggregate: D ← D ∪ D_new. Retrain π. Repeat.

Why it fixes distribution shift: training data now covers states the learner actually visits during deployment — matching the deployment distribution. BC never sees these states.

"DAgger collects data from the learner's policy and queries the expert on the visited states. So it uses the expert as a consultant — it consults the expert at every time and then uses it to add up the data. Once the data is sufficiently added, it does a retraining. That's how it handles the distribution shift that behaviour cloning cannot."

Q1 — Wristband Health Monitor: MAB vs MDP 7.5 marks

EC-2Question 1 — Context
A wristband chooses among Mode A (low power, moderate accuracy), Mode B (medium power, high accuracy), Mode C (high power, very high accuracy) each hour.
Case 1: User activity is independent of modes chosen.
Case 2: Prolonged Mode C → battery temperature rises → future rewards reduced.
(a) Why RL and immediate vs long-term value [1.5 marks]

Why RL: No labelled dataset of correct mode choices exists; rewards come from interaction. The agent must explore different modes and learn from outcomes (trial-and-error). SL requires a fixed input→output mapping; the correct mode depends on dynamic, unobserved user activity.

Immediate reward: monitoring accuracy or battery efficiency from the chosen mode right now.

Long-term value: cumulative discounted reward over hours — e.g., preserving battery by occasionally using Mode A to sustain Mode B/C availability for critical future events.

(b) Classify Case 1 and Case 2 [2 marks]

Case 1 → Multi-Armed Bandit (MAB).
Activity is independent of mode choices; future rewards unaffected by past actions. No state evolves: only choosing among 3 arms to maximise expected immediate reward.
Justification: No state transitions; actions don't affect future reward distributions.

Case 2 → Finite MDP.
Mode C usage raises battery temperature which affects future rewards — the state (battery temperature) now evolves based on action history.
Justification: Actions cause state transitions (temperature rising), creating temporal dependency — the core property of an MDP.

(c) Value Iteration, 1 iteration, γ=0.1 [4 marks]

Initialize V₀=0 for all states. Synchronous Bellman update using diagram transitions:

StateActionQ (with V₀=0)
RestingMode A1.0×(1) = 1.0
RestingMode B0.4×(2) + 0.6×(1) = 1.4 ✓ greedy
ModerateMode A0.4×(2) + 0.6×(1) = 1.4
ModerateMode B0.4×(1) + 0.6×(2) = 1.6 ✓ greedy
HighMode A0.5×(1) + 0.5×(1) = 1.0
HighMode B1.0×(1) = 1.0 (tie)

V₁(Resting)=1.4, V₁(Moderate)=1.6, V₁(High)=1.0.
After 1 iteration: Moderate > Resting > High. Mode B preferred from Resting and Moderate.

Q2 — ICU Ventilator MDP 7.5 marks

(a) MDP Formulation [2.5 marks]

States: {lowO2, OptimalO2, highO2, Stable (terminal)}

Actions: {Increase pressure (I), Decrease pressure (D), Maintain (M)}

Transitions: Maintain always retains state. Increase/Decrease: P(intended effect)=0.6, P(no change)=0.4. Terminal: 4 consecutive Optimal readings → Stable.

Reward: +1 if s'=OptimalO2; 0 otherwise.

\[\text{lowO2} \xrightarrow{\text{I, p=0.6}} \text{OptimalO2} \xrightarrow{\text{I, p=0.6}} \text{highO2}\] \[\text{highO2} \xrightarrow{\text{D, p=0.6}} \text{OptimalO2} \xrightarrow{\times 4\text{ consec.}} \text{Stable}\]

(b) Reward design: Design A vs Design B [2 marks]

Design A: r=+10 for lowO2→OptimalO2 — incentivises correcting dangerous hypoxia.

Design B: r=−10 for OptimalO2→highO2 — penalises over-ventilation.

Prefer Design A in general: it directly incentivises the primary goal (reaching safe SpO₂). Design B only penalises one dangerous transition and provides no guidance for escaping lowO2. Exception: Design B is better if the agent already corrects hypoxia but tends to over-ventilate.

(c) Episodic or continuous? [1.5 marks]

Episodic. The task has a defined terminal state: 4 consecutive optimal SpO₂ readings → patient stabilises → episode ends. Each ICU admission is a finite episode. (Continuous tasks have no terminal and use discounting for infinite sums — this task has a terminal.)

(d) Impact of γ=0.01 on patient stability [1.5 marks]

With γ≈0 the agent is extremely myopic: cares only about the immediate next reward. It optimises one-step SpO₂, ignoring the 4-consecutive-optimal requirement. The AI may oscillate — correcting hypoxia for one step then overshooting to hyperoxia — never achieving stable care. A high γ (e.g., 0.9) is essential to value sustained stabilisation.

(b) Significance of α; effect when α=1 [1.5 marks]

α controls the weight of recent rewards vs. accumulated history. With α=1: Q_{n+1} = R (the Q-value equals the last reward only; all history discarded). This is extremely volatile — the estimate jumps to every new reward with no smoothing. In the pharma platform, α=1 would cause erratic suggestions driven by whatever single intervention last gave a good reward.

(c) Significance of UCB confidence level [1 mark]

The confidence coefficient c controls exploration-exploitation: large c = more exploration (infrequently tried arms get a larger bonus); small c = near-greedy (exploits the currently best-known intervention). UCB provides a principled way to try under-explored interventions until we are statistically confident we haven't missed a better option.

(d) ε-case analysis for steps 1–5 [2 marks]

(i) Definitely ε-case (non-greedy action selected):

  • Step 2: Q(S)=3.5 is highest; T was chosen — definitely exploration (ε-case).
  • Step 3: Q(S)=3.5 highest; R was chosen — definitely ε-case.
  • Step 4: Q(S)=3.5 highest; C was chosen (Q=0, lowest) — definitely ε-case.

(ii) Possibly ε-case (cannot distinguish greedy from random):

  • Step 1: All Q=0 (tied) — any action is greedy, so S could be either. Possibly ε.
  • Step 5: Q(S)=3.5 highest; S chosen — looks greedy, but could have been randomly selected and coincidentally matched the greedy action. Possibly ε.

Q4 — Model-free MDP: Monte Carlo Methods 7.5 marks

EC-2Question 4 — Context
States s₀, s₁. Actions a₁, a₂, a₃. γ=0.8.
Episode: (s₀,a₁,r=2,s₀) → (s₀,a₃,r=0,s₁) → (s₁,a₂,r=3,s₁) → (s₁,a₂,r=−1,terminal).
Initial Q-table: Q(s₀,a₁)=1, Q(s₀,a₂)=0.5, Q(s₀,a₃)=0; Q(s₁,a₁)=0, Q(s₁,a₂)=0.5, Q(s₁,a₃)=1.
ε-soft policy: π(a₁|s₀)=0.5, π(a₂|s₀)=0.3, π(a₃|s₀)=0.2; π(a₁|s₁)=0.2, π(a₂|s₁)=0.5, π(a₃|s₁)=0.3.
(a) Why V_π(s) alone is insufficient for control [2 marks]

\(V_\pi(s)\) tells how good it is to be in state s under π, but not which action to take. Action selection requires: \(a^* = \arg\max_a \sum_{s'} P(s'|s,a)[R(s,a,s') + \gamma V_\pi(s')]\). In a model-free MDP, \(P(s'|s,a)\) is unknown — so knowing V perfectly still can't tell you which action to pick. \(Q_\pi(s,a)\) is needed because it encodes the action directly without requiring the model.

(b) First-visit MC failure with deterministic policy and fix [2 marks]

Why it fails: A deterministic policy always picks the same action a* in each state. Only (s, a*) pairs are ever visited → Q(s,a) for a≠a* is never updated → no evidence to discover better alternatives → stuck in a local optimum.

Fix — Exploring Starts or ε-soft policy:

  • Exploring starts: begin some episodes with random (s₀, a₀) to ensure all state-action pairs are eventually visited.
  • ε-soft policy: assign probability ε/|A| to all actions; greedy action gets (1−ε+ε/|A|). Every action is tried infinitely often in the limit.
(c) First-visit MC update: returns, Q-table, policy [3.5 marks]

Step 1: Compute discounted returns (γ=0.8), working backward:

\(t=3\): terminal, \(G_3 = -1\).
\(t=2\): (s₁, a₂) — first visit: \(G_2 = 3 + 0.8(-1) = 2.2\)
\(t=1\): (s₀, a₃) — first visit: \(G_1 = 0 + 0.8(2.2) = 1.76\)
\(t=0\): (s₀, a₁) — first visit: \(G_0 = 2 + 0.8(1.76) = 3.408\)

(s₁, a₂) at t=3 is skipped — not the first visit to (s₁, a₂).

Step 2: Updated Q-table:

Q(s,a)a₁a₂a₃Changes
s₀3.4080.51.76a₁: 1→3.408; a₃: 0→1.76
s₁02.21a₂: 0.5→2.2

Step 3: Updated ε-soft policy:
New greedy: s₀→a₁ (max Q=3.408); s₁→a₂ (max Q=2.2). Same greedy actions as before, but now backed by much stronger Q-value evidence. The ε-soft probabilities keep the same structure (greedy action gets the highest probability), but Q(s₀,a₁) and Q(s₁,a₂) are now far larger relative to alternatives.

Summary: Q(s₀,a₁): 1→3.408; Q(s₀,a₃): 0→1.76; Q(s₁,a₂): 0.5→2.2. Policy greedy choices unchanged; estimates now more reliable.

Exam Tips from Mam

📌 Key tips from the final discussion
  • UCB formula: Always use natural log (ln, not log base 10). If c is not given, assume c=1. The formula is identical across MAB Module 1 and MCTS Module 4.
  • IS ratio with deterministic policy: If target policy is deterministic and the behavior episode contains an action the target never takes, ρ=0 and the episode contributes nothing. Mention this in your answer.
  • AlphaGo vs AlphaZero: Key distinction is human data vs no human data. AlphaGo uses 30M expert games for the SL policy. AlphaZero starts from scratch.
  • ERWA vs sample average: Know which formula applies — ERWA for non-stationary, sample average for stationary. Know the calculation steps.
  • DAgger vs BC: BC fails because it only trains on expert states. DAgger fixes this by rolling out the learner and querying the expert on those states.
  • Softmax gradient: ∇log π(H|s) = (1 − π(H|s)) × φ(s). Mam called this "beautiful" — the self-regulating property.
  • γ interpretation: Very low γ (≈0) = myopic agent; for tasks needing sustained multi-step plans (like ICU stabilisation), low γ is dangerous.
  • DQN stability: Two techniques only — Experience Replay (breaks correlations) and Target Network (stops chasing moving targets). Not DDQN.
  • ε-case analysis: An action is "definitely ε" if it's clearly NOT the greedy action (lower Q than another). It's "possibly ε" when the chosen action happens to also be the greedy action.
