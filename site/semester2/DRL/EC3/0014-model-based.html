Model-Based vs Model-Free

Every RL algorithm has to answer: "how do I decide which action is good?" Model-free methods (TD, Q-learning, policy gradient) learn from real experience only — every lesson costs a real interaction with the environment. Model-based methods go further: they build a model of the environment and then imagine interactions, learning from both real and simulated experience.

Everyday picture — learning chess

Model-free: play thousands of games, lose or win, update your intuition. Each lesson costs a real game.
Model-based: learn the rules of chess (the model). Then in your head, simulate "what if I moved the bishop here?" — plan through consequences without a single real game.

What is a model?

A model is a learned function \( M(s, a) \rightarrow (s', r) \) — given a state and action, it predicts the next state and reward. It is essentially the agent's internal simulation of the world.

Two flavours of model
  • Distribution model: gives the full probability distribution \( p(s', r \mid s, a) \). Needed for exact planning (DP-style).
  • Sample model: can only sample from \( p(s', r \mid s, a) \) — draw one outcome per query. Sufficient for simulation-based planning.

The core trade-off

A good model gives sample efficiency — you need far fewer real environment steps to learn. But model errors compound: if your model says "this action leads to +10" and reality says "+2", planning inside a wrong model can make things worse than model-free learning.

Exam tip

"Model-based is more sample-efficient but can suffer from model errors" is the one-sentence answer to any compare/contrast question on this topic.

Dyna-Q — Learn, Act, and Plan Together

Dyna-Q (Sutton, 1990) is the simplest model-based RL architecture. It combines three things happening simultaneously: acting in the real environment, learning a model, and using that model to do extra Q-value updates without any additional real experience.

The Dyna-Q loop

After every real step \((S, A, R, S')\), Dyna-Q does two things:

  1. Direct RL update: standard Q-learning update on the real transition.
  2. Model learning: store the transition — \(M(S, A) \leftarrow (S', R)\).
  3. Planning: repeat \(n\) times: sample a random past \((s, a)\) from model, get predicted \((s', r)\), do a Q-learning update on that simulated transition.
$$Q(S,A) \leftarrow Q(S,A) + \alpha\bigl[R + \gamma\max_{a'}Q(S',a') - Q(S,A)\bigr]$$

The formula is identical to Q-learning — the only difference is that in the planning phase, \((S, A, R, S')\) come from the model rather than the real world.

Initialise Q(s,a) ← 0, Model M ← empty
For each real step:
  S ← current state
  A ← ε-greedy action from Q(S,·)
  Take A in real env; observe R, S′
  Direct update: Q(S,A) ← Q(S,A) + α[R + γ max Q(S′,·) − Q(S,A)]
  Model update: M(S,A) ← (R, S′) ← store transition
  Repeat n times: ← planning loop
    s ← random previously-seen state
    a ← random action tried from s
    (r, s′) ← M(s, a)
    Plan update: Q(s,a) ← Q(s,a) + α[r + γ max Q(s′,·) − Q(s,a)]
  S ← S′

Effect of n planning steps

With \(n = 0\), Dyna-Q is identical to pure Q-learning. With \(n = 50\), you get 50 free Q-updates per real step — the agent learns the optimal policy in far fewer real environment interactions. The catch: if the model is wrong (e.g. the environment changed), those 50 updates propagate bad information.

Key insight — planning multiplies experience

Each real step costs one real interaction. Each planning step costs only CPU time. In expensive or dangerous environments (robots, medical trials), this asymmetry is enormous.

UCB — Exploration with a Bonus

All RL agents face the exploration–exploitation dilemma: exploit what you know (choose the action with highest estimated value) or explore (try something uncertain). ε-greedy solves this crudely — explore uniformly at random. UCB (Upper Confidence Bound) is smarter: it explores actions that are either promising or under-tried.

UCB1 formula

$$A_t = \arg\max_a \left[ Q(a) + c \cdot \sqrt{\frac{\ln t}{N(a)}} \right]$$
What each symbol means
  • \(Q(a)\) — current estimated value of action \(a\) (exploitation term)
  • \(N(a)\) — how many times action \(a\) has been tried so far
  • \(t\) — total number of steps taken so far
  • \(c\) — exploration constant: larger \(c\) = more exploration
  • \(\sqrt{\ln t / N(a)}\) — uncertainty bonus: large when \(a\) is rarely tried

The bonus \(c \cdot \sqrt{\ln t / N(a)}\) is an upper confidence bound on the true value: we are saying "action \(a\) might be this good, given how little we know". When \(N(a)\) is small, the bonus is large — we are highly uncertain. When \(N(a)\) grows, the bonus shrinks — we know this action well.

Intuition — the uncertain new restaurant

Your favourite restaurant gives 7/10 every time. A new place has no reviews. UCB says: "I know almost nothing about the new place — it could be 9/10. Let me try it once." After trying it, the uncertainty shrinks and the score either justifies more visits or doesn't.

Worked example — 3 arms

Suppose 3 arms have been tried as follows after 10 total pulls: arm 1 tried 5 times with \(\hat{Q}=2.1\), arm 2 tried 3 times with \(\hat{Q}=5.4\), arm 3 tried 2 times with \(\hat{Q}=3.8\). Use \(c = 1\), \(t = 10\).

$$\text{Arm 1:}\quad 2.1 + 1\cdot\sqrt{\frac{\ln 10}{5}} = 2.1 + \sqrt{\frac{2.303}{5}} = 2.1 + 0.679 = 2.78$$
$$\text{Arm 2:}\quad 5.4 + 1\cdot\sqrt{\frac{\ln 10}{3}} = 5.4 + \sqrt{\frac{2.303}{3}} = 5.4 + 0.876 = 6.28$$
$$\text{Arm 3:}\quad 3.8 + 1\cdot\sqrt{\frac{\ln 10}{2}} = 3.8 + \sqrt{\frac{2.303}{2}} = 3.8 + 1.073 = 4.87$$

UCB picks Arm 2 (score 6.28) even though arm 3 has the largest uncertainty bonus. Arm 2 wins because its estimated value is high enough even after its uncertainty shrinks. After picking arm 2 again, \(N(2) = 4\) and its bonus falls further.

Exam trap — UCB vs ε-greedy

ε-greedy explores randomly. UCB explores targeted — it visits under-tried, high-uncertainty actions. UCB is provably sublinear in regret; ε-greedy is not (unless you anneal ε).

Monte Carlo Tree Search (MCTS)

MCTS is a planning algorithm that builds a search tree incrementally by running many simulations. It does not need a learned value function — instead it estimates action values by averaging returns from simulations. MCTS powers everything from early Go programs to modern AlphaZero.

The four phases

Each MCTS iteration has exactly four steps:

1. Selection

Starting from the root, descend the tree by choosing children according to a tree policy. The standard choice is UCT (UCB applied to trees). Continue until you reach a node that has unexplored children or a terminal node.

2. Expansion

Add one (or more) new child nodes to the selected leaf. Each child represents a previously untried action from that state.

3. Simulation (Rollout)

From the newly expanded node, run a random (or heuristic) simulation to a terminal state. Record the final return \(R\). This is "Monte Carlo" — random sampling to estimate value.

4. Backpropagation

Walk back up the tree from the simulated node to the root. Update every node on the path: increment visit count \(N\) and accumulate value \(W \mathrel{+}= R\). The estimated value is \(Q = W / N\).

UCT — UCB for Trees

In the Selection phase, MCTS uses the UCT formula to choose which child to visit:

$$\text{UCT}(s, a) = \frac{W(s,a)}{N(s,a)} + c \cdot \sqrt{\frac{\ln N(s)}{N(s,a)}}$$

Here \(N(s)\) is the parent's visit count, \(N(s,a)\) is the child's visit count, and \(W(s,a)/N(s,a)\) is the child's average return. This is identical in spirit to UCB1 — exploit good nodes, explore unvisited ones.

Intuition — planning a road trip

You build a tree of possible routes. For each junction, you either follow a known good route (exploitation) or try a road you haven't driven yet (exploration). After reaching a destination (terminal), you drive back mentally and update your notes on every road segment you used.

Why MCTS is powerful

MCTS focuses computation on promising parts of the tree. Branches that are repeatedly selected have good estimates; rarely-visited branches still get explored occasionally due to the UCT bonus. No handcrafted evaluation function is needed — rollouts provide the signal.

AlphaZero — MCTS Guided by a Neural Network

Classical MCTS uses random rollouts for the Simulation phase. AlphaZero replaces the random rollout with a neural network that predicts both the policy (what moves to consider) and the value (how good the position is). The result is an agent that taught itself to be superhuman at chess, shogi, and Go from scratch — no human knowledge, no opening books.

The neural network: two heads

AlphaZero trains a single deep network \( f_\theta(s) = (\mathbf{p}, v) \) with:

Policy head \(\mathbf{p}\)

\(p(a \mid s)\) — a probability distribution over all legal moves from state \(s\). This is the prior used in the Selection phase to bias MCTS toward moves the network thinks are good.

Value head \(v\)

\(v(s) \in [-1, +1]\) — the network's estimate of who will win from state \(s\). This replaces the random rollout in the Simulation phase. No random play needed.

Modified MCTS with network guidance

The Selection phase uses a modified UCT (called PUCT) that incorporates the policy prior:

$$\text{PUCT}(s, a) = Q(s,a) + c \cdot p(a \mid s) \cdot \frac{\sqrt{N(s)}}{1 + N(s,a)}$$

Actions with high prior probability \(p(a \mid s)\) get a larger bonus — the network steers the search toward promising moves, skipping most of the huge branching factor early on.

The self-play training loop

Repeat:
  1. Self-play data generation
    For each game:
      At each position s, run MCTS using f_θ
      Action = sample from MCTS visit counts π(a|s)
      Record (s, π, z) where z = game outcome ∈ {-1, 0, +1}
  2. Network training
    Loss = (v(s) − z)² − π · log p(a|s)
     ↑ value head ↑ policy head (cross-entropy)
    Update θ by gradient descent on loss
  3. Evaluation
    New θ replaces old θ if win rate > threshold
Intuition — learning from your own games

Imagine a chess player who has no coach and no games to study. They play themselves, and after each game, update their intuition: "positions like this were winning; moves like that led to losses." Over millions of games, the intuition becomes extraordinary — better than any human who trained on human games.

Why AlphaZero was revolutionary

  • No human knowledge: no opening theory, no endgame tables, no feature engineering. Just the rules of the game.
  • Generalised: the same algorithm (with no changes) mastered Chess, Shogi, and Go.
  • Superhuman in hours: starting from random play, AlphaZero surpassed Stockfish (best human-tuned chess engine) within 4 hours of training.
  • Sample efficient via MCTS: the network focuses search on the best lines; very few positions are evaluated compared to brute-force search.
Exam: What does the neural network replace?

In classical MCTS, the Simulation phase uses a random rollout to estimate value. AlphaZero replaces this with the network's value head \(v(s)\). The policy head \(p(a|s)\) guides selection (PUCT formula). No random rollout is needed.

Comparison — TD vs Dyna vs MCTS vs AlphaZero

These four approaches span the space from pure model-free to full model-based. Knowing when to use each is a core exam topic.

Property Model-Free TD Dyna-Q MCTS AlphaZero
Model needed? No Learned from data Must be given or simulable Must be given (perfect sim)
Sample efficiency Low Medium (n×boost) High (deep planning) Very high
Compute per step Very low Low–medium High (many rollouts) Very high (GPU + MCTS)
Works without a perfect model? Yes Yes (imperfect model ok) No — needs accurate sim No — needs perfect rules
Works for large state spaces? With function approx With function approx Yes (selective search) Yes (network + search)
Handles stochastic envs? Yes Yes Partially (averaged rollouts) Yes (self-play covers it)
Best use case Unknown envs, no sim available Costly real envs + learnable model Games with fast simulators Perfect-info 2-player games
How to pick in an exam scenario
  1. Is a perfect simulator available? → MCTS or AlphaZero possible.
  2. Is human expertise / data available? → Classical MCTS (use heuristics). If not → AlphaZero (self-play).
  3. Is the environment real (no simulator) but model can be learned? → Dyna-Q.
  4. Is the environment real, complex, and no model can be trusted? → Model-free TD or Policy Gradient.
The spectrum view

These methods form a spectrum from pure experience to pure planning. Dyna-Q is at the middle — it blends both. AlphaZero is at the planning extreme but uses self-generated experience to train the network. Real-world RL often lands somewhere in the middle, adapting the blend based on how expensive real experience is.
