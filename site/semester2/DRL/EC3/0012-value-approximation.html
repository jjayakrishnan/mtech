Why Tabular Methods Fail at Scale

Every algorithm so far — DP, MC, TD — stored one value or Q-value per state. That's fine for toy gridworlds. It becomes catastrophically impractical in the real world.

The Curse of Dimensionality

The number of states grows exponentially with the number of state variables. An Atari game screen is 210×160 pixels, 128 colours each. The number of distinct screens is roughly \(128^{210 \times 160} \approx 10^{33{,}000}\). A Q-table needs one row per state — a table that cannot be allocated on any physical machine, ever.

Three concrete problems

  1. Memory: Even if you discretise a modest 10-variable continuous state space into 100 bins each, you get \(100^{10} = 10^{20}\) states. A 64-bit float for each would take \(8 \times 10^{20}\) bytes — a million times more RAM than all computers on Earth combined.
  2. No generalisation: If you learn \(Q(s_{123}, a) = 7\), it says nothing about \(Q(s_{124}, a)\) even if the two states are visually identical. Every state is an isolated entry. The agent must visit each state separately — billions of times each.
  3. Continuous spaces: Robot joint angles, velocity, temperature — these are real numbers. There are infinitely many states. Tabular storage is fundamentally impossible.
Rigid city map vs a satnav

A tabular agent is like memorising every exact GPS coordinate individually. You've walked Oxford Street at exactly 51.5154°N, 0.1418°W — but 10 cm away is unknown territory. A function approximator is like a satnav: it learns patterns that generalise. If a road looks like one you know, it gives a reasonable estimate — even for positions it has never visited.

The solution: parametric function approximation

Instead of a table \(V(s)\), learn a compact function \(\hat{V}(s, \mathbf{w})\) controlled by a weight vector \(\mathbf{w}\). Similar states automatically produce similar outputs. The weight vector might have thousands of entries — tiny compared to \(10^{33{,}000}\) state-specific values — and it generalises to states never seen before.

Linear Function Approximation

The simplest approximator: a weighted sum of features. Represent state \(s\) as a feature vector \(\mathbf{x}(s) \in \mathbb{R}^d\), then estimate value as:

\( \hat{V}(s,\,\mathbf{w}) \;=\; \mathbf{w}^\top \mathbf{x}(s) \;=\; \sum_{i=1}^{d} w_i\, x_i(s) \)
Feature vectors

Each \(x_i(s)\) is a hand-crafted function extracting one aspect of the state: distance to goal, remaining energy, whether an obstacle is nearby, etc. You choose the features; the algorithm learns the weights.

Worked example — 3 features, 5 states

Setup: 3 features, weights w = [2.0, 1.5, 3.0]
  • \(x_1(s)\) = distance to goal (normalised 0–1)
  • \(x_2(s)\) = energy remaining (normalised 0–1)
  • \(x_3(s)\) = goal is visible (0 or 1)

States: s₀ = [1, 0, 0]   s₁ = [0, 1, 0]   s₂ = [0, 0, 1]   s₃ = [1, 1, 0]   s₄ = [0.5, 0.5, 0.5]

For s₄: \(\hat{V}(s_4) = 2.0 \times 0.5 + 1.5 \times 0.5 + 3.0 \times 0.5 = 1.0 + 0.75 + 1.5 = \mathbf{3.25}\)

Semi-gradient TD update

We adapt TD(0) to update weights. The gradient of the linear approximator is just \(\mathbf{x}(s)\), so:

\( \mathbf{w} \;\leftarrow\; \mathbf{w} \;+\; \alpha\,\delta_t\,\mathbf{x}(S_t) \)

where \(\delta_t = R_{t+1} + \gamma\,\hat{V}(S_{t+1},\mathbf{w}) - \hat{V}(S_t,\mathbf{w})\) is the TD error. Each weight is nudged proportionally to the feature it multiplies — features active in the current state absorb the credit or blame.

Free generalisation

If TD error says we were too pessimistic (\(\delta > 0\)), we boost every weight whose feature was non-zero. Weight \(w_3\) (goal visible) gets boosted — and that boost generalises to every state where the goal is visible, even states never visited. One update helps many states at once.

Exam trap — semi-gradient vs full gradient

The TD target \(R + \gamma\,\hat{V}(S',\mathbf{w})\) depends on \(\mathbf{w}\). When we compute \(\nabla_\mathbf{w}\) we treat the target as a fixed constant and do not differentiate through it. That is why it is called "semi-gradient" — we only use the gradient of the prediction, not the gradient of the target. Differentiating through the target causes oscillation.

SGD and the Mean Squared Value Error

We frame VFA as a regression problem. The mean squared value error (MSVE) measures how far our approximation is from the true value function, weighted by how often each state is visited:

\( \overline{\text{VE}}(\mathbf{w}) \;=\; \sum_{s \in \mathcal{S}} \mu(s)\,\bigl[v_\pi(s) - \hat{V}(s,\mathbf{w})\bigr]^2 \)

where \(\mu(s)\) is the on-policy distribution — states visited more often matter more.

Why MC is true SGD but TD is not

The SGD update on MSVE becomes:

\( \mathbf{w} \;\leftarrow\; \mathbf{w} + \alpha\,\bigl[v_\pi(S_t) - \hat{V}(S_t,\mathbf{w})\bigr]\,\nabla_\mathbf{w}\hat{V}(S_t,\mathbf{w}) \)

We don't know \(v_\pi(S_t)\), so we replace it with a target:

  • MC target: the actual return \(G_t\) — unbiased estimate of \(v_\pi(S_t)\). This is true SGD.
  • TD target: \(R_{t+1} + \gamma\,\hat{V}(S_{t+1},\mathbf{w})\) — biased because it uses the current (wrong) weights. This is semi-gradient: the target contains \(\mathbf{w}\) but we do not differentiate through it.
Why accept the bias?

The MC return \(G_t\) is the sum of all future rewards — one noisy trajectory gives a wildly different number each time (high variance). The TD target uses only one step of reward plus a bootstrap estimate — much lower variance. Semi-gradient TD accepts a small bias in exchange for dramatically more stable gradient estimates.

Bias shrinks as learning progresses

The bootstrap target is biased because \(\hat{V}(S',\mathbf{w})\) is wrong early on. But as \(\mathbf{w}\) improves, the bootstrap target becomes more accurate and the bias shrinks. At convergence, the bias is small enough that the efficiency gain (low variance) is worth it.

Neural Networks as Universal Approximators

Linear VFA can only represent functions of the form \(\mathbf{w}^\top\mathbf{x}(s)\). If the true value function is nonlinear (it almost always is), linear VFA cannot fit it — no matter how many features you engineer. Neural networks solve this: given enough layers and neurons, they can approximate any continuous function to arbitrary precision.

\( \hat{Q}(s,\,a\,;\,\mathbf{w}) \;\approx\; q^*(s,a) \)

The network takes raw state \(s\) as input and outputs Q-values for all actions simultaneously. This is crucial: to pick \(\arg\max_a Q(s,a)\), you need all Q-values — outputting them all in one forward pass costs nothing extra.

DQN Architecture

Input: stacked grayscale frames. Convolutional layers extract spatial features. Fully-connected layers combine them. Output: one Q-value per action.

DQN architecture (Mnih et al. 2015)
  • Input: 4 stacked 84×84 grayscale frames (motion encoded by stacking)
  • Conv1: 32 filters 8×8, stride 4 — detects edges and coarse patterns
  • Conv2: 64 filters 4×4, stride 2 — detects compound patterns
  • Conv3: 64 filters 3×3, stride 1 — fine-grained features
  • FC: 512 units — combines all spatial features
  • Output: \(|\mathcal{A}|\) units (e.g. 18 for Atari) — one Q-value per action, no activation
Why output all actions at once?

If you passed (state, action) together and output a single Q-value, finding the best action would require 18 separate forward passes — one per Atari action. Outputting all Q-values in one pass makes \(\varepsilon\)-greedy action selection essentially free.

DQN's three innovations on top of basic neural Q-learning

Raw Q-learning with a neural network diverges in practice. DQN adds: (1) Experience Replay to break temporal correlation, (2) Target Networks to stabilise the bootstrap target, (3) reward clipping to bound gradient scale. Without (1) and (2), training is unstable and usually fails.

Experience Replay

Training a neural network naively on consecutive RL transitions fails. The reason: temporal correlation. Steps \(t, t{+}1, t{+}2, \ldots\) all come from the same trajectory — the agent is in one room, and all transitions look identical. Neural networks trained on correlated batches memorise the recent path and forget everything else.

The replay buffer

Replay buffer \(\mathcal{D}\)

A FIFO circular buffer of fixed capacity \(N\). Every new transition \((s,a,r,s')\) is appended; when full, the oldest entry is overwritten. At each training step, a random mini-batch of \(B\) transitions is sampled uniformly:

\( \text{Sample: } \bigl\{(s_j,\,a_j,\,r_j,\,s'_j)\bigr\}_{j=1}^{B} \;\sim\; \text{Uniform}(\mathcal{D}) \)

Why random sampling helps

  1. Breaks temporal correlation: A random batch draws from many different episodes. Consecutive transitions in a single trajectory no longer dominate the gradient.
  2. Data reuse: Each experience can be replayed many times — the agent squeezes more learning out of every step taken in the environment.

Key hyperparameters
  • \(N\) — buffer capacity: typically \(10^5\)–\(10^6\). Larger means more diverse data; requires more RAM.
  • \(B\) — mini-batch size: typically 32–64. Larger gives a more stable gradient but is slower per step.
  • Replay start: fill the buffer with ~50,000 random-policy experiences before beginning gradient updates. Ensures diversity from the start.
Exam trap — replay requires off-policy learning

Replaying stored transitions means training on data collected under old, different policies. This is off-policy. You must use Q-learning (not SARSA) in DQN. SARSA evaluates the policy that actually chose the stored action — applying it to replayed data from a different policy is incorrect. Q-learning's max operator makes it valid for any behaviour policy.

Target Network

Even with replay, training can oscillate wildly. The second problem: the TD target is non-stationary. The target is \(r + \gamma\max_{a'}\hat{Q}(s',a';\mathbf{w})\) — it depends on the same \(\mathbf{w}\) we are updating. Every gradient step moves the goalposts. The network chases a target that shifts with every update.

The fix — a frozen copy of the network

Target network \(\mathbf{w}^-\)

Maintain two networks: the online network \(\hat{Q}(s,a;\mathbf{w})\) (updated every step by gradient descent) and the target network \(\hat{Q}(s,a;\mathbf{w}^-)\) (frozen for \(C\) steps). Compute TD targets using the frozen network. Every \(C\) steps, do a hard copy: \(\mathbf{w}^- \leftarrow \mathbf{w}\).

The DQN loss

\( L(\mathbf{w}) \;=\; \mathbb{E}_{(s,a,r,s')\sim\mathcal{D}} \Bigl[\bigl(r + \gamma\max_{a'}\hat{Q}(s',a';\,\mathbf{w}^-) \;-\; \hat{Q}(s,a;\,\mathbf{w})\bigr)^2\Bigr] \)

\(\mathbf{w}^-\) appears only in the target (frozen); \(\mathbf{w}\) only in the prediction (being updated). Gradient flows through \(\hat{Q}(s,a;\mathbf{w})\) only — the target is treated as a constant.

How often to copy? — C steps

Mnih et al. used \(C = 10{,}000\) gradient steps. Too small: target moves too fast → back to instability. Too large: target is stale → slow convergence. \(C\) is a key hyperparameter to tune.

A steady archery instructor

Imagine an archery coach who repositions their own target every time you miss. Impossible to improve. Instead, the coach holds completely still for 10 minutes while you practise, then moves to the next position. That's the target network: a temporarily fixed reference that gives stable learning signal.

The Deadly Triad

DQN works well in practice — but the underlying theory warns of a fundamental instability. Three ingredients, each harmless alone, cause divergence when combined. Sutton & Barto call this the Deadly Triad.

IngredientWhy it's neededWhy it's dangerous in combination
Function approximation Generalise to large/continuous state spaces Errors generalise too — a wrong value for one state corrupts similar states across the entire function
Bootstrapping Online updates without full episodes Updates depend on current estimates; errors in the target propagate backwards through the bootstrap chain and amplify
Off-policy learning Reuse data from any behaviour policy The training distribution (behaviour policy) differs from the target policy; gradients point in a direction misaligned with the actual objective

Baird's counterexample (1995)

Baird proved that combining all three can cause Q-values to diverge to infinity even in a trivially simple MDP with a linear function approximator. The intuition: off-policy samples over-emphasise certain states; the bootstrap update propagates wrong estimates for those states; function approximation spreads the error to neighbouring states, amplifying it — a runaway feedback loop.

DQN's practical mitigations
  • Target networks — slow down the bootstrap feedback loop by freezing the target for \(C\) steps
  • Gradient (Huber loss) clipping — clip the TD error to \([-1,\,1]\); prevents catastrophically large weight updates
  • Reward clipping — all rewards clipped to \(\{-1, 0, +1\}\); bounds the scale of the targets
  • Experience replay — the random batch partially re-balances the off-policy distribution mismatch
A rumour that amplifies

You heard a rumour and told 10 friends (function approximation generalises). Each friend exaggerates slightly and passes it on (bootstrapping amplifies). You are not even in the main spreading circle (off-policy mismatch). Before long the rumour bears no resemblance to reality. Target networks and gradient clipping are the "fact-checkers" inserted into the chain.

Exam tip — the triad explains every DQN design choice

Every unusual choice in DQN is a direct countermeasure to the deadly triad. If asked "why does DQN use X?", trace it: target network → counteracts bootstrapping instability; replay buffer → counteracts off-policy distribution shift; reward clipping → counteracts function approximation error scale. Name the triad component, then the fix.

Full DQN Algorithm (Mnih et al. 2015)

Bringing it all together: replay buffer, target network, and \(\varepsilon\)-greedy exploration.

Initialise replay buffer \(\mathcal{D}\) with capacity \(N\)
Initialise online Q-network: Q(s, a; w) — random weights w
Initialise target Q-network: Q̂(s, a; w⁻) with w⁻ ← w

For each episode:
  Observe initial state s₁ (preprocess: stack 4 grayscale frames)
  For t = 1, 2, ..., T:

    // 1. ε-greedy action selection
    With probability ε:  a_t ← random action
    Otherwise:         a_t ← argmax_a Q(s_t, a; w)

    Execute a_t; observe reward r_t; observe s_{t+1}

    // 2. Store in replay buffer (circular FIFO)
    Store (s_t, a_t, r_t, s_{t+1}) → D

    // 3. Sample random mini-batch
    Sample {(s_j, a_j, r_j, s′_j)}_{j=1..B} ~ Uniform(D)

    // 4. Compute targets using FROZEN target network
    For each j in batch:
      y_j = r_j                               (if s′_j is terminal)
      y_j = r_j + γ max_{a′} Q̂(s′_j, a′; w⁻)  (otherwise)

    // 5. Gradient step on online network ONLY
    Minimise loss: (1/B) Σ_j (y_j − Q(s_j, a_j; w))²
    w ← w − α ∇_w loss     (RMSProp or Adam)

    // 6. Hard copy to target network every C steps
    Every C steps: w⁻ ← w

    // Anneal ε: 1.0 → 0.1 over 1M steps
What made DQN historic
  • Same network, same hyperparameters across 49 Atari 2600 games — zero game-specific tuning
  • Reached superhuman performance on 29 of 49 games from raw pixel input alone
  • First demonstration that a single RL agent could learn diverse complex tasks directly from high-dimensional sensory data
Key hyperparameters from the paper
  • Replay buffer capacity: \(N = 10^6\)
  • Mini-batch size: \(B = 32\)
  • Target update interval: \(C = 10{,}000\) steps
  • Discount factor: \(\gamma = 0.99\)
  • Exploration: \(\varepsilon\) annealed 1.0 → 0.1 over 1M steps, then 0.1 fixed
  • Learning rate: \(\alpha = 0.00025\) with RMSProp (\(\rho = 0.95\))
  • Replay start: 50,000 steps of random play before first gradient update
