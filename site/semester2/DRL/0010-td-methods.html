00 · Overview

Temporal Difference Learning

TD learning fuses the best parts of Dynamic Programming and Monte Carlo. It learns step by step — no model needed, no waiting for the episode to end.

By the end of this lesson you will understand three algorithms — TD(0), SARSA, and Q-learning — and be able to trace each one through a real numeric example.

From the lecture (Session 9 — 4 July 2026): "Temporal difference learning is a mix of both [DP and MC]. Like Monte Carlo you still create samples, but like dynamic programming you can bootstrap. So it doesn't need to terminate; you do a fixed-step look-ahead." — Prof. Rajavadana
01 · Foundations

DP vs Monte Carlo vs TD

Before we learn TD, let's place it next to the two methods you already know. Each one answers the same question — "how good is this state?" — in a different way.

Analogy — three ways to estimate the value of a house.
DP: you have the full blueprint and pricing model. You calculate the value room by room, using your neighbour's value to shortcut the rest.
MC: you don't have the model. So you sell the house, wait until the final sale price is in, then work backwards to decide how good each room was.
TD: you don't have the model and you can't wait for the final sale. So after each open house, you make a running estimate using your current best guess of what the house will sell for.

03 · TD Learning

TD(0) — the core update rule

The simplest TD method is TD(0). It updates the value of a state after each single step. You don't need the full episode to finish.

From Monte Carlo to TD

In Monte Carlo, we update values using the actual total return \(G_t\):

$$ V(S_t) \;\leftarrow\; V(S_t) \;+\; \alpha\bigl[G_t - V(S_t)\bigr] $$

where \(G_t\) is the discounted sum of all future rewards in the episode. We have to wait until the episode ends to compute it.

In TD(0), we replace \(G_t\) with a one-step estimate called the TD target:

$$ V(S_t) \;\leftarrow\; V(S_t) \;+\; \alpha\underbrace{\bigl[\underbrace{R_{t+1} + \gamma V(S_{t+1})}_{\text{TD target}} - V(S_t)\bigr]}_{\text{TD error }\delta_t} $$

Here every symbol means:

  • \(V(S_t)\) — current estimate of the value of state \(S_t\)
  • \(\alpha\) — the learning rate (a small positive number, e.g. 0.1). Controls how big a step we take.
  • \(R_{t+1}\) — the reward we actually received after taking the next step
  • \(\gamma\) — the discount factor (between 0 and 1). Future rewards are worth less.
  • \(V(S_{t+1})\) — our current estimate of the value of the next state
  • \(\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\) — the TD error: how wrong our current estimate was
Intuition: you are driving home. You estimate the drive will take 30 minutes. Ten minutes in, traffic looks light, so you now think the total will be 25 minutes. The TD error is "I was off by 5 minutes; let me update my initial estimate slightly." You don't need to arrive home to make that correction.

04 · TD Learning

TD Target & TD Error — in plain words

Two terms come up constantly in TD learning. Make sure you can tell them apart.

TD Target

\(R_{t+1} + \gamma V(S_{t+1})\)

This is our new estimate of how good state \(S_t\) is. We compute it after taking one step. It combines the reward we just got with our estimate of the next state's value.

TD Error \(\delta_t\)

\(\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\)

This is the surprise — how far our old estimate \(V(S_t)\) was from the new estimate (TD target). Positive means we were too pessimistic. Negative means too optimistic.

Why MC uses accurate returns but TD uses estimated ones. MC waits for the true \(G_t\) — it is unbiased but high-variance (a long noisy trajectory). TD uses an estimate — it is biased (wrong at first) but low-variance (only one step of noise). In practice, the bias drops quickly as \(V\) improves. This bias-variance trade-off is a core idea in all of RL.
05 · TD Control

SARSA — On-Policy TD Control

TD(0) learns state values \(V(s)\). But to control an agent, we need action-value estimates \(Q(s,a)\): "how good is taking action \(a\) in state \(s\)?"

SARSA is the on-policy TD algorithm for learning \(Q\). Its name comes from the five things it uses each step:

S  →  A  →  R  →  S′  →  A′

State · Action · Reward · Next-State · Next-Action

The SARSA update rule

$$ Q(S_t,A_t) \;\leftarrow\; Q(S_t,A_t) + \alpha\bigl[R_{t+1} + \gamma Q(S_{t+1},A_{t+1}) - Q(S_t,A_t)\bigr] $$

This looks exactly like TD(0), but we replace \(V(S)\) with \(Q(S,A)\) everywhere. The TD target is now \(R_{t+1} + \gamma Q(S_{t+1},A_{t+1})\) — we need to know the next action \(A_{t+1}\) before we can update.

On-policy means we improve the policy we are actually following. The next action \(A_{t+1}\) is chosen by the current policy (e.g. ε-greedy), so SARSA takes the policy's caution into account. If the policy is timid and avoids a cliff, SARSA learns that caution.
SARSA algorithm
Initialise Q(s,a) ← 0 for all s, a
For each episode:
  S ← initial state
  A ← choose A from S using policy (e.g. ε-greedy on Q)
  Repeat:
    Take action A; observe R, S′
    A′ ← choose A′ from S′ using policy
    Q(S,A) ← Q(S,A) + α[R + γQ(S′,A′) − Q(S,A)]
    S ← S′; A ← A′
  Until S is terminal

SARSA — Worked Example

The slides use a tiny four-state maze. Let's trace SARSA step by step through it.

The maze

Four states: w, x, y, z arranged in a 2×2 grid. Two exits exist:

  • From w: take action exit → reward +10
  • From z: take action exit → reward −100

All other moves give reward 0. Discount factor \(\gamma = 0.9\). Learning rate \(\alpha = 0.1\) (we will use 1 for clean numbers in the first example). All Q values start at 0.

Press "Next step" to start Episode 1.

Manual trace — Episode 1, Step 1

We start at state x. Policy picks action go to w (or any action, since all Q = 0 so ε-greedy picks randomly).

The agent moves: S = x, A = w, R = 0, S′ = w, A′ = exit (policy picks exit from w).

SARSA update:

$$ Q(x, \text{go-w}) \;\leftarrow\; 0 + 1 \cdot [0 + 0.9 \cdot Q(w,\text{exit}) - 0] $$

Since Q(w, exit) = 0 still, we get \(Q(x, \text{go-w}) = 0\). No change yet — we need to discover the +10 reward first.

Episode 1, Step 2 — reaching the +10 exit

Now S = w, A = exit, R = +10, S′ = terminal.

SARSA update (\(Q(\text{terminal},\cdot)=0\) by definition):

$$ Q(w,\text{exit}) \;\leftarrow\; 0 + 1 \cdot [+10 + 0.9 \cdot 0 - 0] = \mathbf{+10} $$

Now Q(w, exit) = +10. On the next episode, when we are in x and move to w, the SARSA update for Q(x, go-w) will "feel" this +10 through bootstrapping.

Episode 2, Step 1 — value propagates back

Start at x again. S = x, A = go-w, R = 0, S′ = w, A′ = exit.

$$ Q(x,\text{go-w}) \;\leftarrow\; 0 + 1 \cdot [0 + 0.9 \cdot \underbrace{10}_{Q(w,\text{exit})} - 0] = \mathbf{+9} $$

Value has propagated one step back. After more episodes it will reach y, then z, building a path that steers the agent toward the +10 exit and away from the −100 pit.

Key insight: SARSA propagates value backwards one step per episode. The bootstrap shortcut means it doesn't have to wait for the whole trajectory — it corrects itself after every single step.
07 · TD Control

Q-Learning — Off-Policy TD Control

Q-learning is almost identical to SARSA. The only difference is in one word: instead of using the actual next action \(A_{t+1}\), it uses the best possible next action.

The Q-Learning update rule

$$ Q(S_t,A_t) \;\leftarrow\; Q(S_t,A_t) + \alpha\Bigl[R_{t+1} + \gamma \underbrace{\max_{a'} Q(S_{t+1},a')}_{\text{greedy over ALL actions}} - Q(S_t,A_t)\Bigr] $$

The difference from SARSA: we take the maximum Q value at the next state over all possible actions \(a'\). We don't need to first choose \(A_{t+1}\) — we just look at the best available option.

Off-policy means we are learning the values for the optimal greedy policy, even if we are actually following a different (more exploratory) policy. The max-Q bootstrap says "assume we would behave optimally from the next state onwards." SARSA says "assume we behave as our current policy dictates."
Q-Learning algorithm
Initialise Q(s,a) ← 0 for all s, a
For each episode:
  S ← initial state
  Repeat:
    Choose A from S using policy (e.g. ε-greedy on Q)
    Take action A; observe R, S′
    Q(S,A) ← Q(S,A) + α[R + γ maxa′Q(S′,a′) − Q(S,A)]
    S ← S′
  Until S is terminal
(Notice: no A′ needed before the update!)

Q-learning is guaranteed to converge to the optimal action-value function \(q^*\) as long as every state-action pair is visited often enough — a result that follows from the proof of convergence for the Bellman equation.

Manual trace — reaching the −100 pit

Say the agent starts at z, takes action "exit", and falls into the −100 trap. S = z, A = exit, R = −100, S′ = terminal.

$$ Q(z,\text{exit}) \;\leftarrow\; 0 + 1\cdot[-100 + 0.9 \cdot 0 - 0] = \mathbf{-100} $$

Next episode: at state y, the agent considers moving to z. Q-learning updates Q(y, go-z) using maxa′ Q(z, a′).

The max over z's actions is max(Q(z, exit), Q(z, go-y)) = max(−100, 0) = 0.

$$ Q(y,\text{go-z}) \;\leftarrow\; 0 + 1\cdot[0 + 0.9 \cdot 0 - 0] = 0 $$

No propagation yet — but on the episode after, when Q(z, exit) = −100 and Q(z, go-y) = 0, max = 0 still. The punishment only propagates once Q(z, go-y) also becomes negative.

After several episodes, the −100 penalty propagates back: y avoids z, x avoids y, and so on. The agent learns the safe path to +10.

09 · TD Control

SARSA vs Q-Learning — the key difference

SARSA (on-policy)

Uses the actual next action chosen by the current policy in the TD target.

→ If the policy is exploratory (sometimes takes random actions), SARSA learns more cautious Q-values. It respects the risk that the policy might wander near the cliff.

✔ Safer in risky environments

Q-Learning (off-policy)

Uses the best possible next action (max Q) in the TD target.

→ Learns the value of the optimal policy even while following a different one. Ignores exploratory noise. Can find the optimal path faster, but may underestimate risk during training.

✔ Faster convergence to optimal

10 · Extensions

Expected SARSA

SARSA uses the actual next action \(A_{t+1}\). Q-learning uses the best action (max). Expected SARSA splits the difference — it uses the expected Q value over all possible next actions, weighted by how likely the policy is to pick each one.

$$ Q(S_t,A_t) \;\leftarrow\; Q(S_t,A_t) + \alpha\Bigl[R_{t+1} + \gamma \sum_{a'} \pi(a'|S_{t+1})\,Q(S_{t+1},a') - Q(S_t,A_t)\Bigr] $$

where \(\pi(a'|S_{t+1})\) is the probability of choosing action \(a'\) in state \(S_{t+1}\) under the current policy.

Why bother? Sampling a single action (SARSA) adds noise — the actual \(A_{t+1}\) might be a low-probability random action. Taking the expectation removes that noise. Expected SARSA usually converges more smoothly than regular SARSA, at the cost of one extra summation per step.

Example with ε-greedy policy (ε = 0.1, 2 actions)

Say Q(s′, a₁) = 10 and Q(s′, a₂) = 2. Under ε-greedy: action a₁ is greedy (picked with probability 1 − ε + ε/2 = 0.95) and a₂ with probability ε/2 = 0.05.

$$ \mathbb{E}_\pi[Q(s',a')] = 0.95 \times 10 + 0.05 \times 2 = 9.5 + 0.1 = \mathbf{9.6} $$

SARSA would use 10 if it happened to sample a₁, or 2 if it sampled a₂. Expected SARSA always uses 9.6 — more stable, less noisy.

11 · Extensions

Maximisation Bias & Double Learning

Q-learning uses \(\max_{a'} Q(s',a')\). This looks harmless, but it causes a problem called maximisation bias.

The problem

Suppose the true optimal action values at some state are all zero, but our estimates have random noise — some positive, some negative. The max over our noisy estimates will almost always be positive, even though the true max is zero. We are systematically too optimistic.

Analogy. You ask ten unreliable friends what the best restaurant in town is. Each gives you a slightly wrong rating. You pick the highest rating you hear. Because you took the max of noisy guesses, your chosen restaurant will likely disappoint — the max of noise is biased upward.

The fix — Double Learning

Maintain two independent Q-tables, \(Q_1\) and \(Q_2\). Use one to pick the best action, the other to evaluate it:

$$ Q_1(S,A) \;\leftarrow\; Q_1(S,A) + \alpha\bigl[R + \gamma Q_2\bigl(S',\;\arg\max_{a'}Q_1(S',a')\bigr) - Q_1(S,A)\bigr] $$

(The roles of \(Q_1\) and \(Q_2\) are swapped randomly each step.)

By separating selection (which action to try) from evaluation (what value to assign it), the upward bias cancels out. The trade-off: double the memory for Q tables, but the same computation per step.

Key insight: whenever you see a \(\max\) over estimated values in RL, ask: "could this be biased upward?" Double DQN (a famous deep RL algorithm) uses exactly this idea.
12 · Extensions

n-step TD

TD(0) looks one step ahead. Monte Carlo looks all the way to the end. n-step TD lets you choose any depth \(n\) in between.

Building the n-step return

$$ G_{t:t+1} = R_{t+1} + \gamma V(S_{t+1}) \quad\text{(1-step, i.e. TD(0))} $$
$$ G_{t:t+2} = R_{t+1} + \gamma R_{t+2} + \gamma^2 V(S_{t+2}) \quad\text{(2-step)} $$
$$ G_{t:t+n} = \sum_{k=1}^{n} \gamma^{k-1}R_{t+k} + \gamma^n V(S_{t+n}) \quad\text{(n-step)} $$

As \(n \to \infty\), the bootstrapped term \(\gamma^n V(S_{t+n})\) shrinks to zero and \(G_{t:t+n}\) becomes the full MC return \(G_t\). So TD and MC are two ends of the same spectrum.

13 · Wrap-up

Which method when?

This was a major focus in Session 9. The professor gave three use cases to build intuition. Here they are with the reasoning:

ScenarioBest methodWhy
Chess robot Dynamic Programming Rules of chess are fixed and complete. The model dynamics are fully known. You can plan ahead without sampling.
Ball-throwing robot arm Monte Carlo No exact model of physics, but episodes are clear: the ball either lands or misses. You can wait for episode-end feedback. Full-episode returns are natural here.
Autonomous navigation car (live traffic) TD Learning Can't wait for an "episode" to end — traffic changes in real time. No fixed model. Needs step-by-step updates. This is exactly what TD was designed for.
The three questions to ask (from the lecture):
1. Are the model dynamics available and fixed? → If yes, consider DP.
2. Do episodes terminate in reasonable time? → If yes and no model, consider MC.
3. Do you need real-time, online updates? → If yes, use TD.
14 · Wrap-up

Lesson Recap

TD(0) update

\(V(S_t) \leftarrow V(S_t) + \alpha[\underbrace{R_{t+1}+\gamma V(S_{t+1})}_\text{TD target} - V(S_t)]\)

Model-free, one-step bootstrap. Updates after every step.

SARSA (on-policy)

\(Q(S,A) \leftarrow Q(S,A) + \alpha[R+\gamma Q(S',A')-Q(S,A)]\)

Uses the actual next action \(A'\). Cautious, respects the policy's behaviour.

Q-Learning (off-policy)

\(Q(S,A) \leftarrow Q(S,A) + \alpha[R+\gamma\max_{a'}Q(S',a')-Q(S,A)]\)

Uses the best possible next action. Learns the optimal policy directly.

n-step TD

Generalises TD(0) (n=1) to MC (n→∞). The n-step return looks ahead n rewards before bootstrapping.

The one thing to remember: TD = DP's bootstrapping + MC's model-free sampling. SARSA is on-policy (uses actual A′). Q-learning is off-policy (uses max A′). Both converge to optimal Q* given enough exploration.
